# Native Win32 GUI bindings

[`Win32NativeFn`](fun/Win32NativeFn.md) implements the shared `WIN32` GUI contract over generated
original-header descriptors and typed C field adapters. Native pointers
remain in `RuneForeign`; public tokens share `Win32Common.Types` identities.
Use the Windows-width build entrypoint after regenerating the binding set
and compiling its field adapter DLL. Close windows, classes and owned GDI
objects before the provider's explicit `close` operation.

The selected inventory covers all 38 kernel, user and GDI functions in
`ffi/win32/inventory.json`. Additional names, ownership, output parameters,
UTF-16 encodings, callback lifetime and failure policies live in
`ffi/win32/core.ffi`; original SDK headers remain unchanged. Generated raw
descriptors preserve native status codes and original declaration mappings.
The native facade captures errors before conversion or cleanup and uses
deferred callback exceptions to clean up owned results before propagation.

Creation-time callbacks receive the same public window token returned by
`createWindowEx`. Nested sends and destruction use canonical opaque handles;
active paint scopes, selected GDI objects, classes with windows and active
callbacks reject destructive operations. `withPaint` pairs BeginPaint and
EndPaint on success and exception paths. Copied queue messages have single
use: dispatch or explicitly discard each snapshot. Provider shutdown releases
undispatched copies, then closes its generated session.

The public portable subset supports top-level windows with no parent,
extended style 0, class redraw styles, overlapped/visible window styles,
show/hide/restore commands, solid pens, stock pens/brushes, RGB colours and
opaque/transparent text backgrounds. Palette flags, child windows, menus,
dialogs, minimization/maximization requests and synthetic lifecycle/unknown
messages reject explicitly. Incoming unknown messages can use `Default`
inside their original callback context, preserving exact foreign payloads.
Native text uses UTF-16/WTF-8; the cross-provider drawing contract uses ASCII.

Build the shared interactive example with the native provider:

```sh bin/rune --library ffi/win32/native --build examples/win32/native.build \ --path "WIN32_GENERATED=$PWD/ffi/win32/generated/64" -o build/win32-example.rbc RUNE_WIN32_ADAPTER_LIBRARY='<Windows path to the generated 64-bit shim DLL>' \ WSLENV="${WSLENV:+$WSLENV:}RUNE_WIN32_ADAPTER_LIBRARY/w" \ bin/runevm.exe '<Windows path to build/win32-example.rbc>' --smoke```

Use `32` and `runevm32.exe` for x86. Remove `--smoke` for interactive use.
The `WSLENV` bridge is needed when launching a Windows process from WSL;
native Windows launches set the adapter variable in their usual environment.
When a callback synchronously destroys its own window and then returns
`Default`, dispatch completes with the message's failure value without
calling a default procedure on the retired window. Direct operations on
stale window tokens still reject.
The same `examples/win32/app.sml` selects SDL or mock providers through their
separate build entrypoints. `.build` never invokes native compilers or other
commands; generation and adapter compilation are explicit steps.

Reproducible generation and real GUI acceptance use the SML coordinator:

```sh make bin/runeffi bin/rune-win32-check bin/rune-win32-check generate 64 ffi/win32/generated/64 bin/rune-win32-check generate 32 ffi/win32/generated/32 bin/rune-win32-check contract 64 bin/rune-win32-check contract 32 bin/rune-win32-check app 64 bin/rune-win32-check app 32```

Set `RUNEFFI_WINDOWS_SDK` and `RUNEFFI_MSVC_INCLUDE` to the pinned originals
described in `ffi/win32/README.md`. The coordinator generates twice, compares
immutable set identities, compiles field adapters with Clang's MSVC target
against those originals, links DLLs with MinGW, checks the eight integer
helpers against a native C oracle, and runs both interpreters plus x64 JIT
modes with collection stress. The x86 JIT backend remains unavailable.
Runtime users need the matching libffi-enabled VM
and field adapter DLL, not the SDK. M8 completion still requires the recorded
integration and release acceptance gates.

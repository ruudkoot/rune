# Unit testing

Unit tests as values. A test is the unit of a verdict and the checks inside
it are soft. Golden files hold what a test must produce. A suite names its
tests, so a program can list them, filter them and run them as `main`.

| [`EXPECT`](sig/EXPECT.md) | Checks inside a test (docs/plans/unit-testing.md, D3): a test is the unit of verdict, and the checks in it are soft. A check that fails is recorded with its label and the test goes on; the test fails if any of its checks failed, and `fail` ends it at once. A test that raises an exception of its own fails with the exception's name and message. |
| [`GOLDEN`](sig/GOLDEN.md) | Golden files (docs/plans/unit-testing.md, D6): what a test produced, compared with a file that holds what it must produce.

# How the library reads its specification

[The Standard ML Basis Library](README.md)

The notes of the documentation, from the comments of the library. The name of a note is the label of
the check of the test suite that pins it, where there is one.

## Readings

Where the text is silent, ambiguous or contradicts itself, and what it is taken to say.

- `Word.scan/DEC-bare-prefix-0w` &mdash; [`WORD.scan`](sig/WORD.md#val-scan). A prefix that no digit follows is not a prefix, but its leading `0` is a digit: `"0wxg"` scans as 0 and leaves `"wxg"`.
- `Int.mod/minInt-by-minus-one` &mdash; [`INTEGER.mod`](sig/INTEGER.md#val-mod). `mod` never raises [`Overflow`](sig/GENERAL.md#exn-overflow), although `div` does at the same arguments: `minInt mod ~1` is 0.
- `Int.rem/minInt-by-minus-one` &mdash; [`INTEGER.rem`](sig/INTEGER.md#val-rem). As `mod`, it never raises [`Overflow`](sig/GENERAL.md#exn-overflow): `rem (minInt, ~1)` is 0.
- `Int.sameSign/zero-pos` &mdash; [`INTEGER.sameSign`](sig/INTEGER.md#val-samesign). It is "equivalent to `sign i = sign j`", so zero has the same sign as zero only, and not as a positive number.
- `Int.scan/HEX-bare-prefix-0x` &mdash; [`INTEGER.scan`](sig/INTEGER.md#val-scan). A `0x` that no digit follows is not a prefix, but its `0` is a digit: `"0xg"` scans as 0 and leaves `"xg"` in the stream.
- `Array2.region/Subscript-not-Overflow` &mdash; [`ARRAY2.region`](sig/ARRAY2.md#type-region). Whether a region lies inside its array is decided without a sum that could overflow, so a region whose `row + nrows` is no `int` raises [`Subscript`](sig/GENERAL.md#exn-subscript) and never [`Overflow`](sig/GENERAL.md#exn-overflow). `appi`, `foldi` and `modifyi` find that out before `f` is applied to anything, so a bad region changes nothing.
- `Array2.tabulate/traversal-order` &mdash; [`ARRAY2.tabulate`](sig/ARRAY2.md#val-tabulate). "Initialized in traversal order" is read as: `f (0, 0)` is applied first whichever traversal is asked for, and its result fills the array before the rest is computed.
- `Array2.copy/Subscript-dst-nothing-row-beyond` &mdash; [`ARRAY2.copy`](sig/ARRAY2.md#val-copy). The place the region is copied to must be inside `dst` even when the region is empty, so a corner outside `dst` raises although nothing would be copied.
- `Array2.appi/nothing-rows-at-the-end` &mdash; [`ARRAY2.appi`](sig/ARRAY2.md#val-appi). "0 \<= \#row reg \<= nRows" allows a region to begin at the edge of the array: such a region and one of no rows or no columns are valid, and traverse nothing.
- `MONO_ARRAY2.region/at-the-end` &mdash; [`MONO_ARRAY2.region`](sig/MONO_ARRAY2.md#type-region). A region that starts at the edge of the array, and one of no rows or no columns, is valid and covers nothing. *(no check pins it)*
- `Time.zeroTime/lies-in-the-past` &mdash; [`TIME.zeroTime`](sig/TIME.md#val-zerotime). It is "a common reference point for all time values"; the suite takes it to lie in the past, so `now ()` is greater.
- `Time.fmt/fixed-point` &mdash; [`TIME.fmt`](sig/TIME.md#val-fmt). The text has "fixed-point semantics": the digit last kept is rounded to nearest, and since a time holds microseconds every digit past the sixth is a zero.
- `Time.scan/digits-past-the-sixth` &mdash; [`TIME.scan`](sig/TIME.md#val-scan). Any number of digits may be written; those of the fraction after the sixth are dropped rather than rounded, and a number too large for a time raises [`Time`](sig/TIME.md).
- `PRIM_IO.reader/after-close` &mdash; [`PRIM_IO.reader`](sig/PRIM_IO.md#type-reader). Once `close` has been called, every function of the reader but `close` and `getPos` raises [`IO.Io`](sig/IO.md#exn-io) with the cause [`IO.ClosedStream`](sig/IO.md#exn-closedstream). The specification says both that and "raise [`IO.ClosedStream`](sig/IO.md#exn-closedstream)", so the suite accepts either from a reader that Rune did not make. *(no check pins it)*
- `PRIM_IO.writer/after-close` &mdash; [`PRIM_IO.writer`](sig/PRIM_IO.md#type-writer). Once `close` has been called, every function of the writer but `close` raises [`IO.Io`](sig/IO.md#exn-io) with the cause [`IO.ClosedStream`](sig/IO.md#exn-closedstream). *(no check pins it)*
- `PRIM_IO.writer/partial-writes` &mdash; [`PRIM_IO.writer`](sig/PRIM_IO.md#type-writer). A write may write only part of what it was given; [`STREAM_IO`](sig/STREAM_IO.md) retries until everything is written. *(no check pins it)*
- `PrimIO.openVector/readVecNB-is-there` &mdash; [`PRIM_IO.openVector`](sig/PRIM_IO.md#val-openvector). Nothing has to be waited for, so `readVecNB` is present and always `SOME`, with `SOME` of the empty vector once the vector is spent.
- `PrimIO.nullRd/is-a-closed-source` &mdash; [`PRIM_IO.nullRd`](sig/PRIM_IO.md#val-nullrd). It "acts like a reader that is always at end-of-stream": every read gives nothing and waits for nothing, it has no positions, and once closed it behaves as any other closed reader.
- `PrimIO.nullWr/is-a-sink` &mdash; [`PRIM_IO.nullWr`](sig/PRIM_IO.md#val-nullwr). It "serves as a sink": every write reports that it wrote all it was given, and once closed it behaves as any other closed writer.
- `PrimIO.augmentReader/what-cannot-be-built` &mdash; [`PRIM_IO.augmentReader`](sig/PRIM_IO.md#val-augmentreader). What the table does not reach stays `NONE`: there is no non-blocking read without `canInput` or an `NB` operation to build it from, and no blocking read without `block` or a blocking operation.
- `StreamIO.instream/segments-are-shared` &mdash; [`STREAM_IO.instream`](sig/STREAM_IO.md#type-instream). Two streams that share a segment read the same elements from it: the reader is asked for a chunk once, and the chunk stays in the chain. The chain continues past an end of stream, so a stream that was kept from before an end of stream still reads what was there. *(no check pins it)*
- `StreamIO.input/Io-carries-the-reader` &mdash; [`STREAM_IO.input`](sig/STREAM_IO.md#val-input). The page of [`IO`](sig/IO.md) says what the fields hold: the exception the reader raised is the `cause` and the reader's own name is the `name`.
- `StreamIO.inputN/fewer-is-past-the-end-of-stream` &mdash; [`STREAM_IO.inputN`](sig/STREAM_IO.md#val-inputn). When fewer than `n` elements come before an end of stream, the stream returned is the one `inputAll` would give: immediately past that end of stream. Exactly `n` elements that end at one leave the stream before it.
- `StreamIO.canInput/what-is-counted` &mdash; [`STREAM_IO.canInput`](sig/STREAM_IO.md#val-caninput). Counted are the elements already in the chain, then what the reader's `readVecNB` yields, which the stream keeps: such a lookahead commits the stream to those elements. A reader without `readVecNB` is asked for `avail` instead. *(no check pins it)*
- `StreamIO.endOfStream/does-not-consume` &mdash; [`STREAM_IO.endOfStream`](sig/STREAM_IO.md#val-endofstream). It does not move past the end of stream it finds, so it stays `true` until a read consumes it; that read returns the empty vector, and only afterwards are elements that the source gained seen. *(no check pins it)*
- `StreamIO.output/Io-closed-writes-nothing` &mdash; [`STREAM_IO.output`](sig/STREAM_IO.md#val-output). The cause on a closed or terminated stream is `ClosedStream`, from the list of [`IO`](sig/IO.md), and nothing is written.
- `StreamIO.flushOut/empties-first` &mdash; [`STREAM_IO.flushOut`](sig/STREAM_IO.md#val-flushout). The buffer is emptied before it is passed on, so a writer that fails cannot cause the same elements to be written twice. Flushing a terminated or a closed stream does nothing.
- `StreamIO.closeOut/a-failed-flush-leaves-it-open` &mdash; [`STREAM_IO.closeOut`](sig/STREAM_IO.md#val-closeout). Closing an already closed stream does nothing; a terminated one is not flushed; and when the flush fails the stream stays open, so that it can be closed again. What it held is gone all the same: the buffer is emptied before the writer is asked, as `flushOut` does it.
- `StreamIO.getReader/Io-cause-is-ClosedStream` &mdash; [`STREAM_IO.getReader`](sig/STREAM_IO.md#val-getreader). A truncated stream is one that has given its reader away; the cause is `ClosedStream` for it as for a closed one.
- `StreamIO.filePosIn/what-is-unsupported` &mdash; [`STREAM_IO.filePosIn`](sig/STREAM_IO.md#val-fileposin). "Does not support the operation" means that the reader has no `getPos`, and the cause of the [`IO.Io`](sig/IO.md#exn-io) is then `RandomAccessNotSupported`, from the list of [`IO`](sig/IO.md). A reader that has `getPos` may still fail to tell where it is (a pipe), and the chunks read then carry no position, which raises as well.
- `StreamIO.mkOutstream/the-writer-is-augmented` &mdash; [`STREAM_IO.mkOutstream`](sig/STREAM_IO.md#val-mkoutstream). The specification does not say whether the writer is augmented here; this one augments it, and `getWriter` still gives back the writer that was passed in. *(no check pins it)*
- `StreamIO.getWriter/terminated-is-not-closed` &mdash; [`STREAM_IO.getWriter`](sig/STREAM_IO.md#val-getwriter). A stream that is already terminated gives its writer and its mode again without flushing; only a closed one raises.
- `StreamIO.setPosOut/writes-over` &mdash; [`STREAM_IO.setPosOut`](sig/STREAM_IO.md#val-setposout). What is written after it replaces what stood at that position; the stream is not truncated there.
- `IMPERATIVE_IO.input1/passes-the-end-of-stream` &mdash; [`IMPERATIVE_IO.input1`](sig/IMPERATIVE_IO.md#val-input1). An `input1` that returns `NONE` leaves the stream positioned after the end of stream it found, as `StreamIO.inputN (f, 1)` does, so a following `input1` delivers what the source has gained since.
- `IMPERATIVE_IO.inputN/Size-is-about-the-result` &mdash; [`IMPERATIVE_IO.inputN`](sig/IMPERATIVE_IO.md#val-inputn). The specification writes the condition two ways; [`Size`](sig/GENERAL.md#exn-size) is raised when the number of elements to be returned exceeds the greatest length of a vector, as [`STREAM_IO`](sig/STREAM_IO.md) puts it, not when `n` does.
- `IMPERATIVE_IO.inputAll/file-grows` &mdash; [`IMPERATIVE_IO.inputAll`](sig/IMPERATIVE_IO.md#val-inputall). Several ends of stream are real for a file: a read after one delivers what was appended since, so a second `inputAll` need not be empty.
- `IMPERATIVE_IO.lookahead/removes-nothing` &mdash; [`IMPERATIVE_IO.lookahead`](sig/IMPERATIVE_IO.md#val-lookahead). It removes nothing at all, an end of stream included: at one it gives `NONE` and leaves the stream before that end of stream, which a following `input` then consumes.
- `IMPERATIVE_IO.closeIn/drops-what-was-read-ahead` &mdash; [`IMPERATIVE_IO.closeIn`](sig/IMPERATIVE_IO.md#val-closein). Closing "must also replace the functional stream with an empty stream": what the stream had read ahead of the program is dropped, so nothing can be read after `closeIn`. Closing twice is allowed. *(no check pins it)*
- `IMPERATIVE_IO.endOfStream/does-not-consume` &mdash; [`IMPERATIVE_IO.endOfStream`](sig/IMPERATIVE_IO.md#val-endofstream). It does not consume the end of stream it finds: it stays `true` until a read does, that read gives nothing, and only afterwards is what the source gained seen.
- `ArraySlice.slice/Subscript-not-Overflow` &mdash; [`ARRAY_SLICE.slice`](sig/ARRAY_SLICE.md#val-slice). When `i + n` is no `int` the slice does not exist, and [`Subscript`](sig/GENERAL.md#exn-subscript) says so, never [`Overflow`](sig/GENERAL.md#exn-overflow); `subslice`, `copy` and `copyVec` are the same with their sums, and so are the slices of the monomorphic arrays.
- `BIT_FLAGS.fromWord/masks-the-rest` &mdash; [`BIT_FLAGS.fromWord`](sig/BIT_FLAGS.md#val-fromword). The law `toWord o fromWord = (fn w => andb (w, toWord all))` is required for every word, those with bits that no flag of this structure has included: such bits are dropped rather than kept or refused.
- `Bool.scan/wsx-*` &mdash; [`BOOL.scan`](sig/BOOL.md#val-scan). "Initial whitespace" is what [`Char.isSpace`](sig/CHAR.md#val-isspace) accepts, as for [`StringCvt.skipWS`](sig/STRING_CVT.md#val-skipws): the space, and the characters `\t`, `\n`, `\v`, `\f` and `\r`.
- `Bool.fromString/none-not-whitespace-*` &mdash; [`BOOL.fromString`](sig/BOOL.md#val-fromstring). The characters whose codes are next to those of the white space characters (0, 8, 14, 31, 33, 95 and 127) are not white space: a string that begins with one of them gives `NONE`.
- `Byte.byteToChar/high-bytes-are-not-negative` &mdash; [`BYTE.byteToChar`](sig/BYTE.md#val-bytetochar). A byte is an unsigned number: 200 is the character with code 200, and not the one that a signed byte of \~56 would name.
- `Byte.unpackString/sees-the-current-contents` &mdash; [`BYTE.unpackString`](sig/BYTE.md#val-unpackstring). An array can change: the bytes are read when `unpackString` is called, so the string holds what the slice had at that moment and is not touched by a later update.
- `Char.compare/127-128` &mdash; [`CHAR.compare`](sig/CHAR.md#val-compare). The codes are not negative, so 127 comes before 128 and 255 after 0: a character is not a signed byte.
- `Char.isAlpha/latin1` &mdash; [`CHAR.isAscii`](sig/CHAR.md#val-isascii). The classes below are the sets that the specification's discussion lists, whatever the locale: no character above 127 is in any of them, and `toLower` and `toUpper` change the 52 letters of ASCII only.
- `Char.scan/formatting` &mdash; [`CHAR.scan`](sig/CHAR.md#val-scan). A formatting sequence, a backslash, white space and another backslash, stands for nothing. Such sequences are passed over before the character, and after it as well, so that what is left of the stream never begins with one. *(no check pins it)*
- `Char.fromString/printable-only-all-rejected` &mdash; [`CHAR.fromString`](sig/CHAR.md#val-fromstring). A first character outside the printable range, codes 32 to 126, gives `NONE`, and so does a backslash by itself; every other printable character but the double quote, of which below, is converted to itself.
- `Char.fromString/unescaped-double-quote` &mdash; [`CHAR.fromString`](sig/CHAR.md#val-fromstring). The specification has the text read "as allowed in an SML program", where a double quote that no backslash precedes ends a constant and is no character, and names only characters that do not print and bad escapes as what gives `NONE`. The first is followed: a double quote by itself gives `NONE`, as in MLton and SML/NJ, where Poly/ML converts it. The page of [`STRING`](sig/STRING.md) has no such words and lists what stops a scan, so [`String.scan`](sig/STRING.md#val-scan) converts the same double quote; the two pages differ, and each is followed.
- `Char.fromCString/hex-huge-does-not-fit` &mdash; [`CHAR.fromCString`](sig/CHAR.md#val-fromcstring). A `\x` escape whose value is no character gives `NONE` however many digits it has: [`Overflow`](sig/GENERAL.md#exn-overflow) is not raised.
- `Char.fromCString/printable-only-all-converted` &mdash; [`CHAR.fromCString`](sig/CHAR.md#val-fromcstring). Every printable character but the double quote and the backslash is converted to itself, the single quote included; what does not print is rejected.
- `CommandLine.arguments/none-under-the-runner` &mdash; [`COMMAND_LINE.arguments`](sig/COMMAND_LINE.md#val-arguments). Which arguments a program sees is "operating system and implementation-specific": what the system passes after the name, with nothing taken away, and the empty list when it passes none.
- `Date.date/fields-carry-upward` &mdash; [`DATE.date`](sig/DATE.md#val-date). Seconds, minutes, hours, days and months outside their range are carried into the field above, up to the year; an offset is reduced modulo twenty-four hours with the whole days moved into the hours. A local date is normalised by the C library instead.
- `Date.isDst/UTC-has-none` &mdash; [`DATE.isDst`](sig/DATE.md#val-isdst). A date at a fixed offset is not in daylight saving time: `SOME true` is wrong for it, and `NONE` and `SOME false` are both right.
- `Date.localOffset/now-and-modulo-a-day` &mdash; [`DATE.localOffset`](sig/DATE.md#val-localoffset). The specification does not say whether daylight saving time counts, and takes offsets modulo twenty-four hours; the suite accepts the offset in force now, or an hour more, reduced modulo a day, west of UTC.
- `Date.fromTimeUniv/second-it-falls-in` &mdash; [`DATE.fromTimeUniv`](sig/DATE.md#val-fromtimeuniv). The date is that of the second the time falls in: a fraction of a second is dropped, also for times before the epoch, where dropping is towards the earlier second.
- `Date.toTime/read-in-its-own-zone` &mdash; [`DATE.toTime`](sig/DATE.md#val-totime). A date is "interpreted in its own time zone": one at offset `t` west of UTC is the UTC reading of its fields plus `t`. A local date is converted by the C library. *(no check pins it)*
- `Date.compare/ignores-the-offset` &mdash; [`DATE.compare`](sig/DATE.md#val-compare). The fields are compared as they are written: two dates that name the same moment in different zones do not compare equal, and one written later in its own zone is the greater.
- `Date.scan/does-not-validate` &mdash; [`DATE.scan`](sig/DATE.md#val-scan). It reads exactly that layout and checks nothing beyond it: the weekday is taken as written rather than worked out, and the date it gives is a local one (`offset` and `isDst` both `NONE`). So `scan` can give a date that `fmt` and `toString` then refuse. *(no check pins it)*
- `General.exnName/alias-either-name` &mdash; [`GENERAL.exnName`](sig/GENERAL.md#val-exnname). For an exception declared to be another one (`exception E2 = E1`) either name is an answer: the two constructors are the same exception, and which name the implementation kept is its own business.
- `General.exnMessage/returns-*` &mdash; [`GENERAL.exnMessage`](sig/GENERAL.md#val-exnmessage). "The precise format of the message may vary between implementations and locales", so only this is required of it: it returns rather than raising, and it contains `exnName ex`.
- `IEEEReal.scan/huge-exponent` &mdash; [`IEEE_REAL.scan`](sig/IEEE_REAL.md#val-scan). A huge exponent does not raise [`Overflow`](sig/GENERAL.md#exn-overflow): once what has been read of it exceeds 10^8 the digits that follow are not counted, so the exponent that is recorded is large and of the right sign, but not the one that was written. The number it describes is beyond every real anyway. *(no check pins it)*
- `IO.Io/function-is-unqualified` &mdash; [`IO.Io`](sig/IO.md#exn-io). "The name of the function raising the exception" is taken unqualified: `"openIn"`, not `"TextIO.openIn"`, as MLton and SML/NJ take it. Poly/ML writes the qualified name.
- `ListPair.foldrEq/raises-before-applying` &mdash; [`LIST_PAIR.foldrEq`](sig/LIST_PAIR.md#val-foldreq). Folding from the right needs the last pair first, so the ends of both lists are reached before anything is combined: `f` is not applied at all when the lengths differ.
- `ListPair.allEq/left-longer` &mdash; [`LIST_PAIR.allEq`](sig/LIST_PAIR.md#val-alleq). It answers `false` for lists of different lengths rather than raising `UnequalLengths`: it is the one `Eq` function that does not raise.
- `ListPair.allEq/applies-before-lengths-are-known` &mdash; [`LIST_PAIR.allEq`](sig/LIST_PAIR.md#val-alleq). The specification gives both an equivalent expression, which would apply `p` to nothing when the lengths differ, and an implementation note, which walks the lists together and stops at the first pair that fails. The note is what is implemented, and all three other systems do the same: `p` is applied to the pairs of the common prefix before the lengths are known.
- `Math.tan/near-singularity` &mdash; [`MATH.tan`](sig/MATH.md#val-tan). The specification says that `tan` has "infinities at various finite values"; no [`real`](sig/REAL.md#val-fromint) is an odd multiple of pi/2, so the function is finite everywhere, and what is asked of it is only that its magnitude near the singularity be large.
- `Math.pow/one-base-posInf` &mdash; [`MATH.pow`](sig/MATH.md#val-pow). `pow (1.0, y)` is a NaN for an infinite or NaN `y`, as the specification's table says; C99 and IEEE 754-2008 make it 1 instead, and Poly/ML follows them.
- `Math.cosh/negInf` &mdash; [`MATH.cosh`](sig/MATH.md#val-cosh). It is positive infinity at either infinity, which is what the definition gives; the specification's table writes "cosh +-infinity = +-infinity", which cannot be meant, and MLton follows it to the letter.
- `NetHostDB.scan/inet_aton-forms` &mdash; [`NET_HOST_DB.scan`](sig/NET_HOST_DB.md#val-scan). One number, two, three or four may be written, as the C library's `inet_aton` allows: a single part fills all 32 bits, the last of two parts the low 24, the last of three the low 16. "As specified in the C language" fixes how each part is written: `0x` or `0X` begins a hexadecimal number and a leading `0` an octal one.
- `OS.FileSys.readDir/empty-stays-empty` &mdash; [`OS_FILE_SYS.readDir`](sig/OS_FILE_SYS.md#val-readdir). Once the stream is spent it stays spent: `readDir` keeps giving `NONE` however often it is called, until `rewindDir`.
- `OS.IO.kind/other-kinds` &mdash; [`OS_IO.kind`](sig/OS_IO.md#val-kind). "A given implementation may define other iodesc values": the result need not be one of the seven of `Kind`, and the suite allows for that. Here it always is one: what is none of the others is a `device`. *(no check pins it)*
- `OS.IO.poll/closed-SysErr` &mdash; [`OS_IO.poll`](sig/OS_IO.md#val-poll). The specification gives "one of the file descriptors refers to a closed file" as an example of what raises [`OS.SysErr`](sig/OS.md#exn-syserr). The operating system itself reports such a descriptor as ready, so every descriptor is looked at before the wait, and a closed one raises [`OS.SysErr`](sig/OS.md#exn-syserr).
- `OS.Path.fromString/empty-arcs` &mdash; [`OS_PATH.fromString`](sig/OS_PATH.md#val-fromstring). The arcs are the pieces between the separators, empty ones included: `"/"` gives `[""]`, `"//"` gives `["", ""]`, `"a/"` gives `["a", ""]`, and `""` gives no arcs at all. *(no check pins it)*
- `OS.Path.toString/inverts-fromString` &mdash; [`OS_PATH.toString`](sig/OS_PATH.md#val-tostring). "`fromString o toString` is the identity" holds except for the absolute path with no arcs, which no string produces; where it cannot hold, the exception `Path` counts as holding too.
- `OS.Path.getParent/trailing-separator` &mdash; [`OS_PATH.getParent`](sig/OS_PATH.md#val-getparent). For a path that ends in a separator the parent arc is appended after it: `"a/"` gives `"a/.."` and `"a///"` gives `"a///.."`.
- `OS.Path.joinDirFile/undoes-splitDirFile` &mdash; [`OS_PATH.joinDirFile`](sig/OS_PATH.md#val-joindirfile). It undoes `splitDirFile` on every path of the specification's table except the empty one.
- `OS.Path.splitBaseExt/base-keeps-empty-arcs` &mdash; [`OS_PATH.splitBaseExt`](sig/OS_PATH.md#val-splitbaseext). The base is everything to the left of the extension, empty arcs and all: `"a//c.x"` has the base `"a//c"`. *(no check pins it)*
- `OS.Path.mkCanonical/root-current-arc` &mdash; [`OS_PATH.mkCanonical`](sig/OS_PATH.md#val-mkcanonical). `"/."` becomes `"/"`, because "redundant current arcs are removed", although the specification's list of canonical paths has `"/."` among them; every host agrees on `"/"`.
- `OS.Path.mkRelative/what-is-kept` &mdash; [`OS_PATH.mkRelative`](sig/OS_PATH.md#val-mkrelative). `relativeTo` is canonicalised first, while the arcs of `path` are kept as written, a trailing empty arc included: `"/a/b/"` relative to `"/a/c"` is `"../b/"`. A root alone has no arcs to keep.
- `OS.Path.isRoot/double-separator` &mdash; [`OS_PATH.isRoot`](sig/OS_PATH.md#val-isroot). `"/"` is a root and `"//"` is not: the second has an empty arc under the root.
- `OS.Path.concat/keeps-the-parent-arc` &mdash; [`OS_PATH.concat`](sig/OS_PATH.md#val-concat). The arcs of `q` are appended to those of `p` without cancelling: a `p` that ends in the parent arc keeps it. A trailing empty arc of `p` is absorbed by the join.
- `OS.Process.isSuccess/killed-is-not-success` &mdash; [`OS_PROCESS.isSuccess`](sig/OS_PROCESS.md#val-issuccess). A command that a signal ended has not succeeded: from [`UNIX`](sig/UNIX.md), this is true only where [`Posix.Process.fromStatus`](sig/POSIX_PROCESS.md#val-fromstatus) gives `W_EXITED`.
- `OS.Process.system/a-real-shell` &mdash; [`OS_PROCESS.system`](sig/OS_PROCESS.md#val-system). A shell runs the command, so redirection, sequencing and variables work; it runs in the current directory, and `system` returns only once the command is done. What the process has buffered is neither lost nor written twice by running one.
- `OS.Process.exit/what-is-flushed` &mdash; [`OS_PROCESS.exit`](sig/OS_PROCESS.md#val-exit). "Flushes and closes all I/O streams" reaches the streams the library still holds output for, over writers a program supplied; output to a file is held by the VM, which flushes every file itself. *(no check pins it)*
- `OS.Process.getEnv/the-whole-name` &mdash; [`OS_PROCESS.getEnv`](sig/OS_PROCESS.md#val-getenv). The whole name must match: a name that merely begins with one that is set does not, and neither does a name with `"=value"` attached. A command run by `system` inherits this environment and cannot change it.
- `PackWord.subVec/Subscript-not-Overflow` &mdash; [`PACK_WORD.subVec`](sig/PACK_WORD.md#val-subvec). The bound is tested without the product `bytesPerElem * (i + 1)`, so a huge `i` raises [`Subscript`](sig/GENERAL.md#exn-subscript) and not [`Overflow`](sig/GENERAL.md#exn-overflow). *(no check pins it)*
- `Posix.ProcEnv.setuid/own-is-allowed` &mdash; [`POSIX_PROC_ENV.setuid`](sig/POSIX_PROC_ENV.md#val-setuid). Setting the user to the one the process already has is allowed and changes nothing. Becoming another user, the superuser above all, is refused unless the process is privileged already.
- `Posix.ProcEnv.setgid/own-is-allowed` &mdash; [`POSIX_PROC_ENV.setgid`](sig/POSIX_PROC_ENV.md#val-setgid). As for `setuid`: a process may always take the group it has, and only a privileged one may take another.
- `Posix.ProcEnv.getlogin/may-not-be-known` &mdash; [`POSIX_PROC_ENV.getlogin`](sig/POSIX_PROC_ENV.md#val-getlogin). Without a terminal the system may have no login name to give; the suite accepts either [`OS.SysErr`](sig/OS.md#exn-syserr) or a name that is a user of the machine.
- `Posix.ProcEnv.setsid/group-is-the-pid` &mdash; [`POSIX_PROC_ENV.setsid`](sig/POSIX_PROC_ENV.md#val-setsid). The process group it returns is the process's own number, since the process becomes the leader of a group of its own.
- `Posix.ProcEnv.sysconf/no-limit-raises` &mdash; [`POSIX_PROC_ENV.sysconf`](sig/POSIX_PROC_ENV.md#val-sysconf). A variable the system knows but leaves unbounded is reported the same way as an unknown one -- the call gives `~1` and sets no `errno` \-- so this raises for both. *(no check pins it)*
- `Posix.SysDB/missing-raises-SysErr` &mdash; [`POSIX_SYS_DB.getpwuid`](sig/POSIX_SYS_DB.md#val-getpwuid). The C library reports a name it does not find without setting an `errno`; this raises [`OS.SysErr`](sig/OS.md#exn-syserr) for it all the same, since the alternative would be to return something that names nobody.
- `SML90.Sqrt/is-its-own-exception` &mdash; [`SML90.Sqrt`](sig/SML90.md#exn-sqrt). `Sqrt`, `Ln` and `Ord` are exceptions of their own, as MLton and SML/NJ have them. Poly/ML makes all three [`Overflow`](sig/GENERAL.md#exn-overflow), which loses what went wrong.
- `SML90.Ln/is-its-own-exception` &mdash; [`SML90.Ln`](sig/SML90.md#exn-ln). As `Sqrt`: an exception of its own, not [`Overflow`](sig/GENERAL.md#exn-overflow).
- `SML90.Ord/is-its-own-exception` &mdash; [`SML90.Ord`](sig/SML90.md#exn-ord). As `Sqrt`: an exception of its own, not [`Overflow`](sig/GENERAL.md#exn-overflow) and not [`Subscript`](sig/GENERAL.md#exn-subscript).
- `SML90.lookahead/closed-stream-is-empty` &mdash; [`SML90.lookahead`](sig/SML90.md#val-lookahead). A stream that has been closed is at its end, so it gives the empty string as well, and not `Io`. *(no check pins it)*
- `String.extract/SOME-Subscript-not-Overflow-size` &mdash; [`STRING.extract`](sig/STRING.md#val-extract). The bound is tested so that it cannot overflow: an `i` and an `n` whose sum is no `int` raise [`Subscript`](sig/GENERAL.md#exn-subscript), not [`Overflow`](sig/GENERAL.md#exn-overflow).
- `String.scan/as-much-as-possible` &mdash; [`STRING.scan`](sig/STRING.md#val-scan). "The longest prefix" is taken to mean that a character that cannot be read ends the scan rather than failing it, and that an escape that is not one (`"a\\q"`) leaves what came before it. *(no check pins it)*
- `String.fromString/unescaped-double-quote` &mdash; [`STRING.scan`](sig/STRING.md#val-scan). A double quote without a backslash converts to itself, as in SML/NJ and Poly/ML; MLton stops at it. [`Char.scan`](sig/CHAR.md#val-scan) gives `NONE` for it, for the page of [`CHAR`](sig/CHAR.md) has the text read "as allowed in an SML program" and this one does not.
- `String.scan/empty-input-is-SOME-empty` &mdash; [`STRING.scan`](sig/STRING.md#val-scan). Nothing to read is no failure: `fromString ""` is `SOME ""`. `NONE` is for a first character that cannot be read, as in `fromString "\\q"`.
- `String.fromString/format-first` &mdash; [`STRING.fromString`](sig/STRING.md#val-fromstring). A formatting sequence counts as read although it stands for no character, so a text of nothing but such a sequence gives `SOME ""`, and so does one that a bad escape follows.
- `String.fromCString/stops-at-hex-longest-sequence` &mdash; [`STRING.fromCString`](sig/STRING.md#val-fromcstring). A `\x` escape takes "the longest sequence" of hexadecimal digits: `"\x42C"` is one escape of the value 1068, which is no character, and not `\x42` followed by `C`.
- `StringCvt.SCI/carries-negative` &mdash; [`STRING_CVT.realfmt`](sig/STRING_CVT.md#type-realfmt). A constructor carries any `int option`, also one that no format accepts, such as `SCI (SOME ~1)`: [`Size`](sig/GENERAL.md#exn-size) is raised by `fmt`, not by the constructor.
- `StringCvt.padLeft/width-minInt` &mdash; [`STRING_CVT.padLeft`](sig/STRING_CVT.md#val-padleft). For the smallest `int` the difference `i - size s` does not exist as an `int`; `s` is returned all the same, and [`Overflow`](sig/GENERAL.md#exn-overflow) is not raised.
- `StringCvt.splitl/reads-no-further-than-first-failing` &mdash; [`STRING_CVT.splitl`](sig/STRING_CVT.md#val-splitl). "Will often use lookahead characters" is taken to mean exactly one: the character that stops the scan is read from the source, and nothing after it.
- `Substring.triml/Subscript-negative-k` &mdash; [`SUBSTRING.triml`](sig/SUBSTRING.md#val-triml). The specification says that the exception is raised "when `triml k` is evaluated", before the substring is given, so a partial application with a negative `k` raises at once. *(no check pins it)*
- `Substring.triml/position-of-the-empty-result` &mdash; [`SUBSTRING.triml`](sig/SUBSTRING.md#val-triml). When `k` is more than the size the result is empty, and the page does not say where in the string it lies: here at the end of the substring for `triml` and at its start for `trimr`. The suite checks that it is empty and lies inside the same string.
- `Substring.span/equal-strings-built-separately` &mdash; [`SUBSTRING.span`](sig/SUBSTRING.md#val-span). "Unless `s <> s'`" is read as a comparison of the base strings by value: two equal strings that were built separately count as one base.
- `TextIO.StreamIO.inputLine/last-line-without-a-newline` &mdash; [`TEXT_STREAM_IO.inputLine`](sig/TEXT_STREAM_IO.md#val-inputline). A last line that runs into an end of stream gets a newline appended, so that every line returned ends in one, and the stream returned is past that end of stream. At an end of stream itself it is `NONE`. *(no check pins it)*
- `TIMER/only-properties-are-checked` &mdash; [`TIMER`](sig/TIMER.md). What a timer reads is not a value a test can predict; the suite checks that times are not negative, that they do not go backwards, and that the equivalences the specification states hold. A system that does not account for processor time may report real time here. *(no check pins it)*
- `VectorSlice.slice/Subscript-not-Overflow` &mdash; [`VECTOR_SLICE.slice`](sig/VECTOR_SLICE.md#val-slice). When `i + n` is no `int` the slice does not exist, and [`Subscript`](sig/GENERAL.md#exn-subscript) says so, never [`Overflow`](sig/GENERAL.md#exn-overflow); `subslice` is the same, and so are the slices of the monomorphic vectors.
- `VectorSlice.subslice/NONE-Subscript-beyond` &mdash; [`VECTOR_SLICE.subslice`](sig/VECTOR_SLICE.md#val-subslice). The bounds are those of `sl`, not of the vector it is a slice of: a subslice cannot reach back into the rest of the base vector.
- `VectorSlice.appi/index-in-the-slice` &mdash; [`VECTOR_SLICE.appi`](sig/VECTOR_SLICE.md#val-appi). The index is "that of the corresponding element in the slice": it starts at 0 whatever the slice begins at in its base vector. The same holds for `mapi`, `foldli`, `foldri` and `findi`.
- `Posix.TTY.V/distinct-within-a-set` &mdash; [`POSIX_TTY.V.eof`](sig/POSIX_TTY.md#val-v.eof). POSIX lets `min` share its position with `eof`, and `time` with `eol`, because a terminal is either in canonical mode or not; so the positions are distinct within each of the two sets and not across them.
- `Posix.TTY.I/bits-are-posix's` &mdash; [`POSIX_TTY.I.brkint`](sig/POSIX_TTY.md#val-i.brkint). The page says nothing about what bits these flags have; the suite follows POSIX and asks that every named flag of `I` and `L` have non-zero bits of its own inside `all`, comparing through [`SysWord`](sig/WORD.md) rather than through `allSet`.
- `Posix.TTY.TC/not-a-terminal-raises` &mdash; [`POSIX_TTY.TC`](sig/POSIX_TTY.md#str-tc). The page does not say what happens on a descriptor that is not a terminal; POSIX reports `notty`, so every operation here raises [`OS.SysErr`](sig/OS.md#exn-syserr) for one.
- `Posix.IO/what-comes-from-posix` &mdash; [`POSIX_IO`](sig/POSIX_IO.md). Two things the page does not state come from POSIX itself: a descriptor that has just been made has `FD.cloexec` clear, and a process's own lock never blocks it, so `getlk` reports `F_UNLCK` for it. *(no check pins it)*
- `Posix.IO.dup/lowest-available` &mdash; [`POSIX_IO.dup`](sig/POSIX_IO.md#val-dup). "The lowest one available" is read strictly: closing a descriptor that was just opened and then calling `dup` gives that same number back.
- `Posix.IO.getlk/F_UNLCK-means-free` &mdash; [`POSIX_IO.getlk`](sig/POSIX_IO.md#val-getlk). When nothing blocks the described lock, POSIX reports that as an answer of kind `F_UNLCK`; and since a process's own locks never block it, its own lock is reported that way too.
- `Real.rem/exact-multiple-negative-x` &mdash; [`REAL.rem`](sig/REAL.md#val-rem). The sign of a zero remainder is left open: the specification asks for the sign of `x`, and the definition `x - n * y` gives a positive zero.
- `Real.signBit/zeros` &mdash; [`REAL.signBit`](sig/REAL.md#val-signbit). It looks at the bit and not at the value, so it tells the two zeros apart and answers for a NaN as well. *(no check pins it)*
- `Real.toManExp/one` &mdash; [`REAL.toManExp`](sig/REAL.md#val-tomanexp). The specification writes the range of the significand as "1.0 \<= man \* radix \< radix", which for radix 2 means `0.5 <= \|man\| < 1.0`: the convention of C's `frexp`, and not the one that puts the point after the first digit. For a zero, an infinity or a NaN the significand is `x` itself.
- `Real.nextAfter/equal-zeros-returns-r` &mdash; [`REAL.nextAfter`](sig/REAL.md#val-nextafter). "If `r = t` then it returns `r`": the two zeros are equal, so `nextAfter (~0.0, 0.0)` is `~0.0`. C's `nextafter` returns `t` there, and MLton and Poly/ML follow C.
- `Real.realFloor/negzero-sign` &mdash; [`REAL.realFloor`](sig/REAL.md#val-realfloor). The specification is silent about the sign of a zero result; IEEE 754 keeps the sign of the operand, so `realFloor ~0.5` is `~0.0`. The same holds for `realCeil`, `realTrunc` and `realRound`.
- `Real.realRound/tie-half` &mdash; [`REAL.realRound`](sig/REAL.md#val-realround). A value exactly between two whole numbers goes to the even one, as it does for [`round`](sig/REAL.md#val-round): the specification states the rule under [`round`](sig/REAL.md#val-round) alone, and IEEE 754's rounding to an integral value agrees.
- `Real.fromLargeInt/tie-rounds-to-even-down` &mdash; [`REAL.fromLargeInt`](sig/REAL.md#val-fromlargeint). The current rounding mode is used; under the default one a value exactly between two reals goes to the one whose last digit is even, and the digits that are dropped decide the rest.
- `LargeReal/at-least-Real` &mdash; [`REAL.fromLarge`](sig/REAL.md#val-fromlarge). [`LargeReal`](sig/REAL.md) is at least as wide as [`Real`](sig/REAL.md), so this rounds only where it is wider. *(no check pins it)*
- `Real.fmt/SCI-negzero` &mdash; [`REAL.fmt`](sig/REAL.md#val-fmt). A negative zero is written with its sign, because the formats are described as `[~]?` and `signBit` is set; MLton leaves the sign out.
- `Real.fmt/GEN-integral-one` &mdash; [`REAL.fmt`](sig/REAL.md#val-fmt). In `GEN`, a number with no fractional part is written without a point, as C's `gcvt` does, and the shorter of the scientific and the fixed form is taken, a tie going to the fixed one: `fmt (GEN NONE) 1.0` is `"1"` and `fmt (GEN NONE) 1000.0` is `"1E3"`.
- `Real.scan/what-is-left-in-the-stream` &mdash; [`REAL.scan`](sig/REAL.md#val-scan). A point needs a digit after it, and so does the `E` of an exponent with its sign: what does not complete is left in the stream. `"1."` gives 1.0 and leaves the point, `"1E~"` gives 1.0 and leaves `E~`, and `"."`, `"~."` and `".E1"` give `NONE`. Of the words the longest is tried first, so that `"infinit"` gives infinity and leaves `init`.
- `Real.fromString/TO_NEGINF-negative` &mdash; [`REAL.fromString`](sig/REAL.md#val-fromstring). The numeral is rounded in the rounding mode that is in force, as in MLton and in C's `strtod`; SML/NJ and Poly/ML always round to nearest. [`Real32.fromString`](sig/REAL.md#val-fromstring) rounds once, straight to binary32, and not first to binary64.
- `Real.toDecimal/shortest-digits` &mdash; [`REAL.toDecimal`](sig/REAL.md#val-todecimal). The digits are the fewest that `fromDecimal` reads back as the same real, not the exact expansion, which every real has and which is long: `toDecimal 0.1` has the one digit 1, where the real nearest to a tenth has 55. *(no check pins it)*
- `OS.syserror/one-name-one-condition` &mdash; [`OS.syserror`](sig/OS.md#val-syserror). "A unique name" is read as: one condition gives one error and one name, whichever function met it, and different conditions have different names, so `syserror` and `errorName` invert each other.
- `TextIO.flushOut/closed-is-a-no-op` &mdash; [`TEXT_IO.flushOut`](sig/TEXT_IO.md#val-flushout). Through [`STREAM_IO`](sig/STREAM_IO.md) ("a no-op on terminated streams", and a closed stream is terminated too), flushing a closed outstream does nothing rather than raising.
- `TextIO.inputLine/does-not-pass-the-end-of-stream` &mdash; [`TEXT_IO.inputLine`](sig/TEXT_IO.md#val-inputline). An `inputLine` that gives `NONE` does not consume the end of stream it found -- [`TEXT_STREAM_IO.inputLine`](sig/TEXT_STREAM_IO.md#val-inputline) returns no stream in that case, so there is none to move on to -- and it keeps giving `NONE` even after the file has grown. Poly/ML reads on there.
- `TextIO.outputSubstr/Io-function-is-output` &mdash; [`TEXT_IO.outputSubstr`](sig/TEXT_IO.md#val-outputsubstr). It is "equivalent to `output`", so the `function` of an [`IO.Io`](sig/IO.md#exn-io) it raises is `"output"`, as MLton and Poly/ML report it. SML/NJ reports `"outputSubstr"`.
- `TextIO.scanStream/moves-only-on-success` &mdash; [`TEXT_IO.scanStream`](sig/TEXT_IO.md#val-scanstream). By the implementation the page gives, the stream is moved to where the scanner stopped when it returns `SOME`, and not at all when it returns `NONE`, whatever the scanner read while trying.
- `Unix.execute/current-directory` &mdash; [`UNIX.execute`](sig/UNIX.md#val-execute). The page does not say which directory the child runs in; it is this process's current one.
- `Unix.reap/status-is-remembered` &mdash; [`UNIX.reap`](sig/UNIX.md#val-reap). The status is kept, so reaping the same process again gives the same answer rather than failing. A child that is merely stopped does not end the wait, since [`Posix.Process.W.untraced`](sig/POSIX_PROCESS.md#val-w.untraced) is not asked for. *(no check pins it)*
- `Unix.exit/flushes` &mdash; [`UNIX.exit`](sig/UNIX.md#val-exit). It runs the [`OS.Process.atExit`](sig/OS_PROCESS.md#val-atexit) actions and then leaves through the VM's exit, which flushes every file; that is taken to satisfy "flushes and closes all I/O streams".
- `Socket.AF.fromString/without-the-prefix` &mdash; [`SOCKET.AF.fromString`](sig/SOCKET.md#val-af.fromstring). A name is the C constant without its leading `"AF_"`: `"INET"` and `"UNIX"`, so `"AF_INET"` gives `NONE`.
- `Socket.shutdown/peer-sees-the-end` &mdash; [`SOCKET.shutdown`](sig/SOCKET.md#val-shutdown). The page says only that "further sends will be disallowed"; the other end of a socket shut down for sending sees the end of its stream, after everything sent before it has arrived.
- `Socket.recvVec/zero-returns-at-once` &mdash; [`SOCKET.recvVec`](sig/SOCKET.md#val-recvvec). "If `n` is 0 the empty vector is returned": it is returned at once, without waiting for anything, where the system's own call would wait.
- `Socket.recvVecNB/zero-is-SOME` &mdash; [`SOCKET.recvVecNB`](sig/SOCKET.md#val-recvvecnb). Since `recvVec (sock, 0)` gives the empty vector without waiting, `recvVecNB (sock, 0)` is `SOME` of the empty vector and not `NONE`, however little has arrived.
- `Posix.Process.exec/args-and-path` &mdash; [`POSIX_PROCESS.exec`](sig/POSIX_PROCESS.md#val-exec). The first item of `args` is the new program's argument zero and is passed as it stands, not replaced by `path`. And `path` is a pathname: a name with no slash in it is not looked for along `PATH`, which is what `execp` is for.
- `Posix.Process.W.untraced/needed-for-stopped` &mdash; [`POSIX_PROCESS.W.untraced`](sig/POSIX_PROCESS.md#val-w.untraced). Without it a child that is merely stopped does not end the wait: `waitpid_nh` gives `NONE`. *(no check pins it)*
- `Posix.Process.alarm/zero-cancels` &mdash; [`POSIX_PROCESS.alarm`](sig/POSIX_PROCESS.md#val-alarm). A time of zero asks for no alarm, as POSIX has it, so it cancels the outstanding one and still reports the time that was left of it.
- `Posix.Process.sleep/time-left` &mdash; [`POSIX_PROCESS.sleep`](sig/POSIX_PROCESS.md#val-sleep). The page does not say what the result is; it is POSIX's "time left", which is zero when the wait ran out and the rest when a signal cut it short.
- `Posix.FileSys/empty-path-raises` &mdash; [`POSIX_FILE_SYS`](sig/POSIX_FILE_SYS.md). An empty path raises [`OS.SysErr`](sig/OS.md#exn-syserr) with `noent`, as the system would, although inside the library the empty string means "use the descriptor instead". *(no check pins it)*
- `Posix.FileSys.O.noctty/only-for-terminals` &mdash; [`POSIX_FILE_SYS.O.noctty`](sig/POSIX_FILE_SYS.md#val-o.noctty). A regular file never becomes a controlling terminal, so on one this flag is only checked to leave reading as it was. *(no check pins it)*
- `Posix.FileSys.createf/existing-file-is-opened` &mdash; [`POSIX_FILE_SYS.createf`](sig/POSIX_FILE_SYS.md#val-createf). The page speaks of the permissions only for a file that has to be made, so a file that is there already is opened as it stands: neither its contents nor its permissions are touched, unless `O.trunc` is given.
- `Posix.FileSys.umask/not-for-chmod` &mdash; [`POSIX_FILE_SYS.umask`](sig/POSIX_FILE_SYS.md#val-umask). The mask applies to files that are created; `chmod` sets what it is given, mask or no mask.
- `Posix.FileSys.ST.ctime/utime-sets-it-to-now` &mdash; [`POSIX_FILE_SYS.ST.ctime`](sig/POSIX_FILE_SYS.md#val-st.ctime). `utime` changes this time to now, not to either of the times it is given: it is the record that changed, not the contents.
- `Posix.Error/which-error-is-posix's` &mdash; [`POSIX_ERROR`](sig/POSIX_ERROR.md). Which condition a failing call reports is prescribed by POSIX and not by this library; where POSIX allows two, the suite accepts either.
- `Posix.Error.pipe/or-the-signal` &mdash; [`POSIX_ERROR.pipe`](sig/POSIX_ERROR.md#val-pipe). Writing to such a pipe either ends the writer with [`Posix.Signal.pipe`](sig/POSIX_SIGNAL.md#val-pipe) or, when that signal is ignored or caught, fails with this condition; the suite accepts both.
- `WideChar.isAlpha/ascii-classes` &mdash; [`CHAR`](sig/CHAR.md), in `WideChar`. "In WideChar, the functions toLower, toUpper, isAlpha, ... and, in general, the definition of a letter are locale-dependent": here they are those of ASCII, so a character above 127 is in no class and is its own upper and lower case. MLton reads it so too.
- `WideString.scan/reads-wide-characters` &mdash; [`STRING`](sig/STRING.md), in `WideString`. As the signature of the specification writes it, `scan` reads a stream of the structure's own characters, where MLton's reads 8-bit ones; `toString`, `fromString`, `toCString` and `fromCString` take and give text of `char`, the 8-bit one, in which a character above 255 appears as the escape `\uXXXX` or `\UXXXXXXXX` (widechar.sml).
- `WideString.scan/unescaped-double-quote` &mdash; [`STRING`](sig/STRING.md), in `WideString`. In the stream of wide characters an escape is written with the characters of ASCII, and a character that needs none stands for itself, those above 255 too. A double quote that no backslash precedes converts to itself, as it does for [`String.scan`](sig/STRING.md#val-scan) and for [`WideString.fromString`](sig/STRING.md#val-fromstring) on its text of `char`: what ends a scan is the end of the stream, a character that does not print and a bad escape, and a double quote is none of these.

## Errata

Where the specification is wrong.

- `WORD/fmt-Ow` &mdash; [`WORD.fmt`](sig/WORD.md#val-fmt). The specification writes the hexadecimal prefix of the samples as `Ow` with the letter O; it is `0w` with the digit zero. *(no check pins it)*
- `MONO_VECTOR/WideCharVector-must-admit-equality` &mdash; [`MONO_VECTOR`](sig/MONO_VECTOR.md). The page writes `type vector`, not `eqtype`, so that a family whose elements do not admit equality can have a vector -- [`RealVector`](sig/MONO_VECTOR.md) needs that. Where a vector has to admit equality the page says so on the instance instead: [`CharVector`](sig/MONO_VECTOR.md) is declared `where type vector = String.string`, and [`STRING`](sig/STRING.md) writes `eqtype string`. \*\*[`WideCharVector`](sig/MONO_VECTOR.md) is declared `where type elem = WideChar.char` and nothing more, and that is not enough.\*\* [`TEXT`](sig/TEXT.md) shares [`String.string`](sig/STRING.md#type-string) with [`CharVector.vector`](sig/MONO_VECTOR.md#type-vector), and [`WideText`](sig/TEXT.md) is declared `where type String.string = WideString.string`, so [`WideText.CharVector.vector`](sig/MONO_VECTOR.md#type-vector) is [`WideString.string`](sig/STRING.md#type-string), which [`STRING`](sig/STRING.md) makes an equality type. Any implementation whose [`WideText.CharVector`](sig/TEXT.md#str-charvector) is the top-level [`WideCharVector`](sig/MONO_VECTOR.md) \-- every one that has both -- must therefore give [`WideCharVector.vector`](sig/MONO_VECTOR.md#type-vector) equality, and the declaration the page gives it cannot. \*\*The whole of the defect is one missing constraint\*\*: `where type vector = WideString.string`, which [`CharVector`](sig/MONO_VECTOR.md) has and [`WideCharVector`](sig/MONO_VECTOR.md) does not. That makes this a milder fault than the one on the page of [`ARRAY2`](sig/ARRAY2.md), where no constraint can help because there is no type to pin to; here [`WideString.string`](sig/STRING.md#type-string) is already there and [`STRING`](sig/STRING.md) already makes it an equality type. *(no check pins it)*
- `ARRAY2/sub-indices` &mdash; [`ARRAY2`](sig/ARRAY2.md). The specification's description of `sub` says that "`i` gives the row index, and gives the column index"; the second is `j`. *(no check pins it)*
- `ARRAY2/sealed-and-equal-at-any-element` &mdash; [`ARRAY2`](sig/ARRAY2.md). The page asks for three things that Standard ML cannot give together: it declares `structure Array2 :> ARRAY2`, it writes `eqtype 'a array`, and it says "Thus, the type `ty array` admits equality even if `ty` does not". Any two hold; all three cannot, because only the built-in type names of the language admit equality whatever they hold -- `ref`, which the Definition names in Section 4.4, and the `array` of the top level -- and no signature can specify such a type name: through `eqtype 'a t`, a `ty t` admits equality exactly when `ty` does, so an opaque seal makes a fresh type name and the third clause fails at [`real`](sig/REAL.md#val-fromint) and at a function type. The reading taken here is that the seal and `eqtype 'a array` stand and the sentence does not apply, as it is read in MLton and in SML/NJ: [`Array2.array`](sig/ARRAY2.md#val-array) is abstract, and `real Array2.array` admits no equality. Poly/ML takes the other reading and leaves the type a record, which lets a program reach into it.
- `MONO_ARRAY2/instance-constraints` &mdash; [`MONO_ARRAY2`](sig/MONO_ARRAY2.md). The specification writes the identity of [`vector`](sig/VECTOR.md#val-fromlist) with the family's vector and of `elem` with its element as constraints on the structure; they are checked in the suite instead, structure by structure. *(no check pins it)*
- `PRIM_IO/slices-of-the-instances` &mdash; [`PRIM_IO`](sig/PRIM_IO.md). The specification leaves `vector_slice` and `array_slice` abstract; in [`TextPrimIO`](sig/PRIM_IO.md) and [`BinPrimIO`](sig/PRIM_IO.md) they are the slice types of the corresponding structures, which is what every implementation does and what the suite relies on. *(no check pins it)*
- `ARRAY/array-spec` &mdash; [`ARRAY`](sig/ARRAY.md). The specification writes `eqtype 'a array = 'a array`, which the Definition does not allow as a specification; it is written here as an abbreviation of the top-level `array`, which admits equality whatever its element type is. *(no check pins it)*
- `BOOL/bool-spec` &mdash; [`BOOL.bool`](sig/BOOL.md#type-bool). The specification writes `datatype bool = false \| true`. The Definition (Section 2.9) does not allow `true` and `false` to be specified, so the signature replicates the top-level datatype instead; the meaning is the same. *(no check pins it)*
- `CHAR/string-types` &mdash; [`CHAR`](sig/CHAR.md). The specification writes the types of `toString`, `scan`, `fromString`, `toCString` and `fromCString` with [`String.string`](sig/STRING.md#type-string) and [`Char.char`](sig/CHAR.md#type-char) rather than with the `string` and `char` of the signature, because the text is always one of 8-bit characters, also for [`WideChar`](sig/CHAR.md). They are kept as written; that [`Char.char`](sig/CHAR.md#type-char) is `char` and [`Char.string`](sig/CHAR.md#type-string) is [`String.string`](sig/STRING.md#type-string) is a constraint on the structure [`Char`](sig/CHAR.md). *(no check pins it)*
- `CHAR/fromString-sample` &mdash; [`CHAR`](sig/CHAR.md). The third example of the page's table for `fromString` is not the text of an SML string; the page of [`STRING`](sig/STRING.md) has the table as it was meant.
- `GENERAL/exn-spec` &mdash; [`GENERAL.exn`](sig/GENERAL.md#type-exn). The specification writes `type exn = exn`, which is read as: the type of this structure is the top-level one. *(no check pins it)*
- `GENERAL/domain-math` &mdash; [`GENERAL.Domain`](sig/GENERAL.md#exn-domain). The specification says that the functions of [`MATH`](sig/MATH.md) raise it. They do not: a mathematical function answers with a NaN or an infinity instead, and it is [`REAL`](sig/REAL.md) and [`INT_INF`](sig/INT_INF.md) that raise [`Domain`](sig/GENERAL.md#exn-domain).
- `GENERAL/exnMessage-example` &mdash; [`GENERAL.exnMessage`](sig/GENERAL.md#val-exnmessage). The specification's example `exnMessage Div = "Div"` contradicts that freedom; it is an example of one possible format, not a rule. *(no check pins it)*
- `LIST/list-spec` &mdash; [`LIST.list`](sig/LIST.md#type-list). The specification writes the datatype out in the signature. The Definition (Section 2.9) does not allow `nil` and `::` to be specified, so the signature replicates the top-level datatype instead; the meaning is the same. *(no check pins it)*
- `OPTION/option-spec` &mdash; [`OPTION.option`](sig/OPTION.md#type-option). `NONE` and `SOME` may be specified, unlike the constructors of [`bool`](sig/BOOL.md#type-bool) and [`list`](sig/LIST.md#type-list), so the datatype stands here as the specification writes it. *(no check pins it)*
- `POSIX_PROC_ENV/flexible-types` &mdash; [`POSIX_PROC_ENV`](sig/POSIX_PROC_ENV.md). The types `pid` and `file_desc` are left flexible here, as on the page; [`POSIX`](sig/POSIX.md) fixes `pid` to [`Posix.Process.pid`](sig/POSIX_PROCESS.md#type-pid), and `file_desc` is the one `FileSys` and [`IO`](sig/IO.md) use. *(no check pins it)*
- `POSIX_SYS_DB/flexible-types` &mdash; [`POSIX_SYS_DB`](sig/POSIX_SYS_DB.md). The types `uid` and `gid` are left flexible here, as on the page, which says only that they are "identical to [`Posix.ProcEnv.uid`](sig/POSIX_PROC_ENV.md#type-uid)"; [`POSIX`](sig/POSIX.md) fixes them. *(no check pins it)*
- `STRING/string-types` &mdash; [`STRING`](sig/STRING.md). The specification writes the types of `toString`, `scan`, `fromString`, `toCString` and `fromCString` with [`String.string`](sig/STRING.md#type-string), because the text of an escape is always of 8-bit characters, also for [`WideString`](sig/STRING.md). They are kept as written. *(no check pins it)*
- `SUBSTRING/span-exception` &mdash; [`SUBSTRING`](sig/SUBSTRING.md). The specification does not say in the signature that `span` raises an exception, although its description does; the exception is [`General.Span`](sig/GENERAL.md#exn-span). *(no check pins it)*
- `Substring.position/none-ends-after-the-substring` &mdash; [`SUBSTRING.position`](sig/SUBSTRING.md#val-position). The specification describes the second component as "the longest suffix of `ss` that has `s` as a prefix", and then writes the condition on the index in a way that forgets that the occurrence has to lie inside `ss`: an `s` that begins in `ss` and runs past its end is not an occurrence.
- `VECTOR/vector-spec` &mdash; [`VECTOR`](sig/VECTOR.md). The specification writes `eqtype 'a vector = 'a vector`, which the Definition does not allow as a specification; it is written here as an abbreviation of the top-level [`vector`](sig/VECTOR.md#val-fromlist), which admits equality when its element type does. *(no check pins it)*
- `POSIX_TTY/flexible-types` &mdash; [`POSIX_TTY`](sig/POSIX_TTY.md). The types `pid` and `file_desc` are left flexible here, as on the page; [`POSIX`](sig/POSIX.md) fixes them. *(no check pins it)*
- `POSIX_IO/flexible-types` &mdash; [`POSIX_IO`](sig/POSIX_IO.md). The types are kept as the page writes them; the identities that [`POSIX`](sig/POSIX.md) states in its `where type` clauses -- `pid` is [`Posix.Process.pid`](sig/POSIX_PROCESS.md#type-pid), `file_desc` is [`Posix.ProcEnv.file_desc`](sig/POSIX_PROC_ENV.md#type-file_desc), and `open_mode` is [`Posix.FileSys.open_mode`](sig/POSIX_FILE_SYS.md#type-open_mode) \-- are checked in the suite rather than written here. *(no check pins it)*
- `REAL/scan-grammar-grouping` &mdash; [`REAL.scan`](sig/REAL.md#val-scan). The grammars of `scan` and of the formats of [`StringCvt.realfmt`](sig/STRING_CVT.md#type-realfmt) lost their grouping on the pages. They are read as `[+~-]?([0-9]+(\.[0-9]+)? \| \.[0-9]+)([eE][+~-]?[0-9]+)?`, so that the sign belongs to every alternative and the exponent may follow either. *(no check pins it)*
- `OS/opaque-in-the-page` &mdash; [`OS`](sig/OS.md). The page declares `structure OS :> OS`, so the types that no `where` clause fixes are abstract; the suite matches [`OS`](sig/OS.md) against this signature both transparently and opaquely. *(no check pins it)*
- `TEXT/vector-constraint` &mdash; [`TEXT`](sig/TEXT.md). The specification writes the identity of [`CharVector.vector`](sig/MONO_VECTOR.md#type-vector) with [`String.string`](sig/STRING.md#type-string) as one more `sharing` constraint. It cannot be written after the constraint on [`String.string`](sig/STRING.md#type-string) itself (Definition, rule 64: the type is no longer flexible), so it is checked on values in the suite instead.
- `TEXT_IO/include-rewritten` &mdash; [`TEXT_IO`](sig/TEXT_IO.md). The page writes `include IMPERATIVE_IO` and then specifies [`StreamIO`](fun/StreamIO.md) again as a [`TEXT_STREAM_IO`](sig/TEXT_STREAM_IO.md), which is not valid SML. What it means is that a structure matching [`TEXT_IO`](sig/TEXT_IO.md) also matches [`IMPERATIVE_IO`](sig/IMPERATIVE_IO.md) and has a [`StreamIO`](fun/StreamIO.md) matching [`TEXT_STREAM_IO`](sig/TEXT_STREAM_IO.md); that is what stands here, with the substructure first, then the members of [`IMPERATIVE_IO`](sig/IMPERATIVE_IO.md) in full, then the ones of [`TEXT_IO`](sig/TEXT_IO.md). *(no check pins it)*
- `UNIX/opaque-in-the-page` &mdash; [`UNIX`](sig/UNIX.md). The page declares `structure Unix :> UNIX`, so `signal` is abstract there; the suite checks that it is [`Posix.Signal.signal`](sig/POSIX_SIGNAL.md#type-signal) and that `exit_status` is [`Posix.Process.exit_status`](sig/POSIX_PROCESS.md#type-exit_status), which the page requires where both structures exist *(no check pins it)*
- `SOCKET/recvVecFrom-type-variable` &mdash; [`SOCKET`](sig/SOCKET.md). The page gives `recvVecFrom` and the three like it the result `Word8Vector.vector * 'sock_type sock_addr`, a type variable that occurs nowhere else in the type. That is a slip for `'af`: the address a message came from is in the family of the socket, as it is for `recvArrFrom`, and as the description says. It is written `'af` here. *(no check pins it)*
- `POSIX_PROCESS/flexible-types` &mdash; [`POSIX_PROCESS`](sig/POSIX_PROCESS.md). The types `signal` and `pid` are left flexible here, as on the page; [`POSIX`](sig/POSIX.md) fixes `signal` to [`Posix.Signal.signal`](sig/POSIX_SIGNAL.md#type-signal), and the identities stated only in the text are checked in the suite rather than written into the signature.
- `POSIX_FILE_SYS/flexible-types` &mdash; [`POSIX_FILE_SYS`](sig/POSIX_FILE_SYS.md). The types are kept as the page writes them. What the text says about them is checked in the suite rather than written here: `uid`, `gid` and `file_desc` are those of [`Posix.ProcEnv`](sig/POSIX.md#str-procenv), `dirstream` is [`OS.FileSys.dirstream`](sig/OS_FILE_SYS.md#type-dirstream), and `access_mode` is [`OS.FileSys.access_mode`](sig/OS_FILE_SYS.md#type-access_mode). *(no check pins it)*
- `POSIX_ERROR.syserror/spec-writes-OS.Process` &mdash; [`POSIX_ERROR`](sig/POSIX_ERROR.md). The page writes `eqtype syserror = OS.Process.syserror`; [`OS.Process`](sig/OS.md#str-process) has no such type, the description says it "is identical to the type [`OS.syserror`](sig/OS.md#val-syserror)", and `eqtype t = ty` is not a specification SML allows. It is written `type syserror = OS.syserror`, which admits equality. *(no check pins it)*
- `POSIX/opaque-in-the-page` &mdash; [`POSIX`](sig/POSIX.md). The page declares `structure Posix :> POSIX`, so the types that no `where` clause fixes are abstract; the suite matches [`Posix`](sig/POSIX.md) against this signature both transparently and opaquely.

## Deviations

Where the library departs from the specification.

- `MONO_VECTOR_EQ/not-in-the-specification` &mdash; [`MONO_VECTOR_EQ`](sig/MONO_VECTOR_EQ.md). This signature is not in the specification, and it is here because the specification asks for something it gives no way to say: [`WideCharVector.vector`](sig/MONO_VECTOR.md#type-vector) has to admit equality, and the declaration the page gives [`WideCharVector`](sig/MONO_VECTOR.md) cannot make it -- see the erratum `MONO_VECTOR/WideCharVector-must-admit-equality`. [`MONO_VECTOR`](sig/MONO_VECTOR.md) writes `type vector`, not `eqtype`, so that a family whose elements do not admit equality can have a vector; a family whose vector is a type of its own and does admit it is sealed with this instead. The specification's own way out is `where type vector = WideString.string` on the instance, which Rune cannot use because [`WideString`](sig/STRING.md) is declared after [`WideCharVector`](sig/MONO_VECTOR.md) and is built on it -- [`WideString.string`](sig/STRING.md#type-string) must be a type name of its own for wide string constants to be overloaded at it. *(no check pins it)*
- `IMPERATIVE_IO.instream/admits-equality` &mdash; [`IMPERATIVE_IO.instream`](sig/IMPERATIVE_IO.md#type-instream). The specification leaves the type abstract, and a program should not rely on more. In Rune it is a datatype holding a `ref`, so `=` may be written between two instreams and is true exactly when they are the same stream; the same holds for `outstream`.
- `StreamIO/takes-the-slice-structures` &mdash; in `StreamIO`. The specification gives this functor no slice structures, yet it has to hand its writer vector slices, and [`PRIM_IO`](sig/PRIM_IO.md) offers no way to make one. Like MLton's, this one also takes [`VectorSlice`](sig/VECTOR_SLICE.md) and [`ArraySlice`](sig/ARRAY_SLICE.md), and its [`PrimIO`](fun/PrimIO.md) must have positions of the integer type of [`Position`](sig/INTEGER.md), which `filePosIn` counts with. *(no check pins it)*
- `INET6_SOCK/not-in-the-specification` &mdash; [`INET6_SOCK`](sig/INET6_SOCK.md). This signature is not in the specification, which has no IPv6 at all: it was written before the protocol, its [`NetHostDB`](sig/NET_HOST_DB.md) is defined to give the four dotted numbers of IPv4, and it names no structure for anything else. A program that uses this one does not port. What the specification does allow is the family: AF.list "returns a list of all the available address families", so [`Socket.AF`](sig/SOCKET.md#str-af) knowing `INET6` is not a departure and this signature is. *(no check pins it)*
- `TEXT_IO/WideTextIO-not-matched` &mdash; [`TEXT_IO`](sig/TEXT_IO.md). The optional `WideTextIO` is not matched against this signature, because the types here are written `string` and `char`; the suite checks that its readers and writers match [`PRIM_IO`](sig/PRIM_IO.md), and that its vectors are the strings of [`WideString`](sig/STRING.md) and its elements the characters of [`WideChar`](sig/CHAR.md), instead.

## Choices of the implementation

What the specification leaves open, and what the library does.

- `Word.word/64-bits` &mdash; [`WORD.word`](sig/WORD.md#type-word). [`Word.word`](sig/WORD.md#type-word) is the top-level `word`, of 64 bits, and so are [`LargeWord`](sig/WORD.md), [`SysWord`](sig/WORD.md) and [`Word64`](sig/WORD.md); [`Word8`](sig/WORD.md), [`Word16`](sig/WORD.md) and [`Word32`](sig/WORD.md) are kept in a word of the machine whose upper bits are zero. *(no check pins it)*
- `Word.word/constants-overloaded` &mdash; [`WORD.word`](sig/WORD.md#type-word). A word constant has the word type that its context asks for, [`Word8.word`](sig/WORD.md#type-word) as well as `word`, and is checked against the range of that type when the program is compiled; `~` is there for words too. Integer constants are overloaded at [`IntInf.int`](sig/INTEGER.md#type-int) and the `IntN`, real ones at [`Real32.real`](sig/REAL.md#type-real), and character and string constants at [`WideChar.char`](sig/CHAR.md#type-char) and [`WideString.string`](sig/STRING.md#type-string). *(no check pins it)*
- `Int.int/64-bits` &mdash; [`INTEGER.int`](sig/INTEGER.md#type-int). [`Int.int`](sig/INTEGER.md#type-int) is the top-level `int`, of 64 bits, and so are [`Int64`](sig/INTEGER.md), [`FixedInt`](sig/INTEGER.md) and [`Position`](sig/INTEGER.md); [`Int8`](sig/INTEGER.md), [`Int16`](sig/INTEGER.md) and [`Int32`](sig/INTEGER.md) keep a value of their own width, and [`LargeInt`](sig/INTEGER.md) is [`IntInf`](sig/INT_INF.md), which has no width. Constants of each are checked against its range where they are written. *(no check pins it)*
- `MONO_VECTOR.vector/abstract-over-the-polymorphic-one` &mdash; [`MONO_VECTOR.vector`](sig/MONO_VECTOR.md#type-vector). A monomorphic vector is the polymorphic vector of its elements underneath -- the vectors of characters are strings, which the specification requires -- but the type is abstract: an [`IntVector.vector`](sig/MONO_VECTOR.md#type-vector) is no `int vector` for a program, as it is none in MLton or SML/NJ. The arrays and the two-dimensional arrays are the same. Sealing them costs nothing: the instruction counts of `runevm --count` do not change at all, because no file of the library goes between the two. No check of the suite can pin this -- that a type is abstract is not something a program can observe at run time -- and what holds it is the page of the types that are one type, which `make check` compares with the library as it stands. *(no check pins it)*
- `MONO_VECTOR.maxLen/value` &mdash; [`MONO_VECTOR.maxLen`](sig/MONO_VECTOR.md#val-maxlen). The same bound as [`Vector.maxLen`](sig/VECTOR.md#val-maxlen) for the families built on the polymorphic vectors, and [`String.maxSize`](sig/STRING.md#val-maxsize) for those whose vector is a string. *(no check pins it)*
- `Word8Array.array/one-value-per-byte` &mdash; [`MONO_ARRAY`](sig/MONO_ARRAY.md). A [`Word8Array.array`](sig/MONO_ARRAY.md#val-array) is an ordinary array with one value of the machine per byte. *(no check pins it)*
- `MONO_ARRAY.maxLen/value` &mdash; [`MONO_ARRAY.maxLen`](sig/MONO_ARRAY.md#val-maxlen). [`Array.maxLen`](sig/ARRAY.md#val-maxlen), 100,000,000, for every instance, those of characters and of bytes too.
- `MONO_VECTOR_EQ.maxLen/value` &mdash; [`MONO_VECTOR_EQ.maxLen`](sig/MONO_VECTOR_EQ.md#val-maxlen). [`String.maxSize`](sig/STRING.md#val-maxsize), the bound of the families of [`MONO_VECTOR`](sig/MONO_VECTOR.md) whose vector is a string. *(no check pins it)*
- `CharVectorSlice.slice/substring` &mdash; [`MONO_VECTOR_SLICE`](sig/MONO_VECTOR_SLICE.md). The slice of a vector of characters is [`Substring.substring`](sig/SUBSTRING.md#val-substring), and the slice of one of bytes is a substring too. *(no check pins it)*
- `Array2.array/Size` &mdash; [`ARRAY2.array`](sig/ARRAY2.md#val-array). How large is too large is not fixed: an array is too large when the number of its elements is no `int`, or when it exceeds what an array can hold.
- `MONO_ARRAY2.array/abstract-over-Array2` &mdash; [`MONO_ARRAY2.array`](sig/MONO_ARRAY2.md#val-array). An [`IntArray2.array`](sig/MONO_ARRAY2.md#val-array) is an [`Array2.array`](sig/ARRAY2.md#val-array) of its elements underneath, but the type is abstract. It is built on the implementation beneath the sealed [`Array2`](sig/ARRAY2.md) rather than on [`Array2`](sig/ARRAY2.md) itself, because this signature asks for an `eqtype array` and a sealed `'a Array2.array` gives none at [`real`](sig/REAL.md#val-fromint) \-- see the erratum `ARRAY2/sealed-and-equal-at-any-element`. As for [`MONO_VECTOR.vector`](sig/MONO_VECTOR.md#type-vector), no check can pin an abstract type; what holds it is the page of the types that are one type. *(no check pins it)*
- `TIME.time/is-microseconds` &mdash; [`TIME`](sig/TIME.md). A time is a number of microseconds held in an `int`, which reaches about 292,000 years either way. Anything finer than a microsecond is lost, and `zeroTime` is the epoch of the system's clock, 1 January 1970 UTC. *(no check pins it)*
- `Time.toNanoseconds/beyond-64-bits` &mdash; [`TIME.toNanoseconds`](sig/TIME.md#val-tonanoseconds). The result is a [`LargeInt.int`](sig/INTEGER.md#type-int) and is exact however large it is; a [`LargeInt`](sig/INTEGER.md) of bounded precision would raise [`Overflow`](sig/GENERAL.md#exn-overflow) instead.
- `Time.fromSeconds/range-is-open` &mdash; [`TIME.fromSeconds`](sig/TIME.md#val-fromseconds). Where the range ends is not fixed; the suite asks only that a value either come out exact or raise [`Time`](sig/TIME.md), never something else and never a wrong number.
- `Time.+/exact-until-it-raises` &mdash; [`TIME.+`](sig/TIME.md#val-op-plus). Wherever the range ends, doubling a time over and over stays exact until one step raises [`Time`](sig/TIME.md); no step gives a wrong value or another exception.
- `Time.-/exact-until-it-raises` &mdash; [`TIME.-`](sig/TIME.md#val-op-minus). As for `+`: exact until a step raises [`Time`](sig/TIME.md).
- `PRIM_IO.pos/of-the-instances` &mdash; [`PRIM_IO.pos`](sig/PRIM_IO.md#type-pos). [`BinPrimIO.pos`](sig/PRIM_IO.md#type-pos) is the integer type of [`Position`](sig/INTEGER.md), and a position is the offset of a byte from the start of the file, so `compare` is the order of those numbers. [`TextPrimIO.pos`](sig/PRIM_IO.md#type-pos) is abstract, as the specification leaves it: a program can compare positions and give them back to `setPos`, and nothing more. [`WideTextPrimIO.pos`](sig/PRIM_IO.md#type-pos) is abstract as well, and a type of its own: nothing says that a position in a stream of wide characters is one of a stream of characters.
- `PRIM_IO.reader/what-a-file-has` &mdash; [`PRIM_IO.reader`](sig/PRIM_IO.md#type-reader). The readers Rune makes for a file offer `readVec`, `avail`, `close` and `ioDesc`, and the positions only when the file has them; `augmentReader` derives the rest that can be derived. Their `chunkSize` is 4096, and so is a writer's. A file is a handle of the VM, 0, 1 and 2 for the standard ones, and `ioDesc` is the descriptor of the system under it.
- `PrimIO.augmentWriter/the-whole-table` &mdash; [`PRIM_IO.augmentWriter`](sig/PRIM_IO.md#val-augmentwriter). The same table as for a reader, turned around: every row of it is built, an operation the writer has is kept as it is, and what cannot be reached stays `NONE`.
- `StreamIO.getPosOut/is-a-file-offset` &mdash; [`STREAM_IO.getPosOut`](sig/STREAM_IO.md#val-getposout). For a stream over a file the position is the offset of a byte from the start of it, which is what [`BinPrimIO.pos`](sig/PRIM_IO.md#type-pos) holds.
- `IMPERATIVE_IO/functor-is-sealed` &mdash; [`IMPERATIVE_IO`](sig/IMPERATIVE_IO.md). The functor [`ImperativeIO`](fun/ImperativeIO.md) is ascribed this signature, so what it gives a program is what the signature names. The library's own `RuneImperativeIOFn`, which it is built on, is not: [`TextIO`](sig/TEXT_IO.md), [`BinIO`](sig/BIN_IO.md) and `WideTextIO` take the streams apart, and the constructors are not in this signature. *(no check pins it)*
- `StreamIO/LINE_BUF-is-BLOCK_BUF` &mdash; in `StreamIO`. No element of an arbitrary type is known to be a newline, so a stream built here treats `LINE_BUF` as a synonym for `BLOCK_BUF`, as the specification asks of a binary stream. *(no check pins it)*
- `Array.maxLen/value` &mdash; [`ARRAY.maxLen`](sig/ARRAY.md#val-maxlen). 100000000, the same as [`Vector.maxLen`](sig/VECTOR.md#val-maxlen). *(no check pins it)*
- `BinIO.openOut/bytes-are-characters` &mdash; [`BIN_IO.openOut`](sig/BIN_IO.md#val-openout). A byte written here is the character of the same code read by [`TEXT_IO`](sig/TEXT_IO.md), and the other way round: on POSIX nothing is translated between the two, for all 256 values.
- `BIT_FLAGS.all/every-bit-the-system-has` &mdash; [`BIT_FLAGS.all`](sig/BIT_FLAGS.md#val-all). It is every bit of the underlying C value, so it may include flags the specification does not name (`O_CLOEXEC`, `O_LARGEFILE`); that is what lets those survive a trip through `fromWord` or a call that reads the flags back from the system. *(no check pins it)*
- `Byte/free` &mdash; [`BYTE`](sig/BYTE.md). A [`Word8Vector.vector`](sig/MONO_VECTOR.md#type-vector) is a `string` in this library, so `bytesToString` and `stringToBytes` copy nothing. *(no check pins it)*
- `Char.char/eight-bits` &mdash; [`CHAR.char`](sig/CHAR.md#type-char). [`Char.char`](sig/CHAR.md#type-char) is the top-level `char`, a character of 8 bits: its codes run from 0 to 255. *(no check pins it)*
- `Char.maxOrd/value` &mdash; [`CHAR.maxOrd`](sig/CHAR.md#val-maxord). 255 for [`Char`](sig/CHAR.md), and 1114111, the last code point of Unicode, for [`WideChar`](sig/CHAR.md).
- `CommandLine.name/system` &mdash; [`COMMAND_LINE.name`](sig/COMMAND_LINE.md#val-name). What the operating system passed to the program, which need not be a path that leads to it.
- `DATE/the-C-calendar` &mdash; [`DATE`](sig/DATE.md). Local dates are converted by the C library, so the local zone is the machine's and the calendar is the one it keeps; dates at a fixed offset, and UTC, are computed with the proleptic Gregorian calendar, which is how "leap years follow the Gregorian calendar" is read for years before it was adopted. *(no check pins it)*
- `Date.date/any-year` &mdash; [`DATE.date`](sig/DATE.md#val-date). The calendar of a date at an offset is computed and not looked up, so any year that is an `int` has its dates, the year \~5 and the year 100000 too. The specification asks for the years from about 1900 to 2200 only, and the suite takes a date or [`Date`](sig/DATE.md) beyond the range of a 32-bit `time_t`. `toTime` raises [`Date`](sig/DATE.md) from about the year 292000 on, where the microseconds no longer fit, and `fmt` for a year that C's `int` of 32 bits cannot hold. *(no check pins it)*
- `Date.fromTimeLocal/the-machines-zone` &mdash; [`DATE.fromTimeLocal`](sig/DATE.md#val-fromtimelocal). Which zone that is depends on the machine, so the suite's checks of local dates are written to hold in any of them: the offset is `NONE`, whole minutes, and less than a day from UTC.
- `Date.fmt/strftime-in-the-C-locale` &mdash; [`DATE.fmt`](sig/DATE.md#val-fmt). The work is done by `strftime` in the "C" locale as it stood when the program started; only the directives the specification lists are passed on, and any other `%c` gives `c`. The specification names no text for `%Z` on a UTC date, and the suite accepts `"UTC"`, `"GMT"`, `"Z"` or nothing.
- `Date.fmt/zone-names` &mdash; [`DATE.fmt`](sig/DATE.md#val-fmt). `%Z` is the C library's name of the zone for a local date, `UTC` for a date at the offset zero and nothing for one at any other offset. A `%` that ends the format is written as it is. *(no check pins it)*
- `General.Overflow/bounded-int` &mdash; [`GENERAL.Overflow`](sig/GENERAL.md#exn-overflow). Whether an operation can overflow depends on the precision of the type: nothing overflows at [`IntInf.int`](sig/INTEGER.md#type-int), which has none.
- `General.Size/maxLen` &mdash; [`GENERAL.Size`](sig/GENERAL.md#exn-size). What is too large depends on the type: [`String.maxSize`](sig/STRING.md#val-maxsize) and [`Array.maxLen`](sig/ARRAY.md#val-maxlen) say where the bound is.
- `General.exnMessage/format` &mdash; [`GENERAL.exnMessage`](sig/GENERAL.md#val-exnmessage). `"Fail: "` and the argument for a [`Fail`](sig/GENERAL.md#exn-fail), and `exnName ex` for everything else. *(no check pins it)*
- `GenericSock.socket'/protocol-numbers` &mdash; [`GENERIC_SOCK`](sig/GENERIC_SOCK.md). The protocol numbers are IANA's, so 6 is TCP and 17 is UDP.
- `IEEEReal.setRoundingMode/fesetround` &mdash; [`IEEE_REAL.setRoundingMode`](sig/IEEE_REAL.md#val-setroundingmode). The mode of the C library, set with `fesetround`. *(no check pins it)*
- `INET_SOCK/ipv4-only` &mdash; [`INET_SOCK`](sig/INET_SOCK.md). This signature is the specification's, and the specification's Internet sockets are IPv4: an address here is an `in_addr` of [`NetHostDB`](sig/NET_HOST_DB.md) and a port. IPv6 is in [`INET6_SOCK`](sig/INET6_SOCK.md), which is Rune's own and has the same shape for 128-bit addresses. *(no check pins it)*
- `INetSock.UDP.socket'/protocol-numbers` &mdash; [`INET_SOCK.UDP.socket'`](sig/INET_SOCK.md#val-udp.socket-prime). The numbers are IANA's, so 17 is UDP; 0 asks the system to choose, which makes it the same as `socket ()`.
- `IntInf.int/limbs` &mdash; [`INT_INF`](sig/INT_INF.md). A sign and a list of digits in base 2^30, written in SML on top of the 64-bit `int`; equal numbers are equal values, so `=` compares them. [`LargeInt`](sig/INTEGER.md) is [`IntInf`](sig/INT_INF.md). *(no check pins it)*
- `INT_INF/constants` &mdash; [`INT_INF`](sig/INT_INF.md). An integer constant may have the type [`IntInf.int`](sig/INTEGER.md#type-int), and then be of any size, and the overloaded operators work at it. The specification promises neither, so the suite builds its numbers with `fromInt`, `fromString` and arithmetic. *(no check pins it)*
- `Math.pi/nearest-double` &mdash; [`MATH.pi`](sig/MATH.md#val-pi). The [`real`](sig/REAL.md#val-fromint) nearest to pi, which differs from it by about 1.2E\~16.
- `Math.sqrt/four` &mdash; [`MATH.sqrt`](sig/MATH.md#val-sqrt). IEEE 754 requires the square root to be correctly rounded, so an exact square gives its root exactly: `sqrt 4.0` is `2.0`, not something near it.
- `NetHostDB.in_addr/is-dotted-text` &mdash; [`NET_HOST_DB`](sig/NET_HOST_DB.md). An address is the canonical dotted text of an IPv4 address, so `=` compares addresses and not the text they were written as; there is no IPv6 here. *(no check pins it)*
- `NetHostDB.in_addr/abstract` &mdash; [`NET_HOST_DB`](sig/NET_HOST_DB.md). The specification leaves `in_addr` and `addr_family` abstract, and so are they here: `toString` and `fromString` are the way in and out of an address, and [`Socket.AF`](sig/SOCKET.md#str-af) names the families. *(no check pins it)*
- `NetHostDB.getHostName/is-the-nodename` &mdash; [`NET_HOST_DB.getHostName`](sig/NET_HOST_DB.md#val-gethostname). The "standard hostname" is the `nodename` that [`Posix.ProcEnv.uname`](sig/POSIX_PROC_ENV.md#val-uname) reports.
- `OS.FileSys/errors-are-SysErr` &mdash; [`OS_FILE_SYS`](sig/OS_FILE_SYS.md). Every failure raises [`OS.SysErr`](sig/OS.md#exn-syserr) carrying the reason the system gave; no operation here has an exception of its own. *(no check pins it)*
- `OS.FileSys.mkDir/mode` &mdash; [`OS_FILE_SYS.mkDir`](sig/OS_FILE_SYS.md#val-mkdir). The directory gets every permission that the mask of the process leaves, as [`Posix.FileSys.mkdir`](sig/POSIX_FILE_SYS.md#val-mkdir) with the mode 0777 would give it. *(no check pins it)*
- `OS.FileSys.modTime/whole-seconds` &mdash; [`OS_FILE_SYS.modTime`](sig/OS_FILE_SYS.md#val-modtime). The VM passes on the whole seconds of the time that the file system keeps, so the time has no fraction. *(no check pins it)*
- `OS.FileSys.setTime/what-a-check-can-assume` &mdash; [`OS_FILE_SYS.setTime`](sig/OS_FILE_SYS.md#val-settime). The range of a [`Time.time`](sig/TIME.md#type-time) is the implementation's, so the suite builds the times it sets inside the checks; and because the file system may keep whole seconds only, "now" is checked with a second of slack either way.
- `OS.FileSys.access/depends-on-the-process` &mdash; [`OS_FILE_SYS.access`](sig/OS_FILE_SYS.md#val-access). Whether a file counts as executable is the system's affair, and a privileged process may read and write whatever the permission bits say, so the suite's checks of the bits hold only for an ordinary process.
- `OS.FileSys.hash/device-and-inode` &mdash; [`OS_FILE_SYS.hash`](sig/OS_FILE_SYS.md#val-hash). It is the device number times 65599 plus the inode number, in wrapping word arithmetic. "Well distributed modulo 2^n" is checked only as far as a test can: the same file hashes the same, and sixteen files do not all agree in the lowest bit.
- `OS.IO.iodesc/descriptor` &mdash; [`OS_IO.iodesc`](sig/OS_IO.md#type-iodesc). The file descriptor of the operating system, a small integer in a datatype of its own. *(no check pins it)*
- `OS.IO.hash/descriptor-number` &mdash; [`OS_IO.hash`](sig/OS_IO.md#val-hash). The hash is the number of the descriptor, and two `iodesc` are equal when the numbers are: the `iodesc` of the reader under [`TextIO.stdIn`](sig/TEXT_IO.md#val-stdin) is `Posix.FileSys.fdToIOD Posix.FileSys.stdin`.
- `OS.IO.kind/what-is-looked-at` &mdash; [`OS_IO.kind`](sig/OS_IO.md#val-kind). The kind is that of the open file, so a descriptor that was opened through a symbolic link has the kind of what the link names and never `symlink`. A descriptor is a `tty` exactly when [`Posix.ProcEnv.isatty`](sig/POSIX_PROC_ENV.md#val-isatty) says so, which is asked first: `/dev/null` is a `device`.
- `OS.IO.poll_desc/a-descriptor-and-its-conditions` &mdash; [`OS_IO.poll_desc`](sig/OS_IO.md#type-poll_desc). A `poll_desc` is the descriptor with the set of conditions asked for, so asking twice is asking once, the order of asking does not matter, and one that asks for input is not equal to one that asks for output.
- `OS.IO.pollDesc/always` &mdash; [`OS_IO.pollDesc`](sig/OS_IO.md#val-polldesc). Every descriptor can be polled: the answer is never `NONE`. *(no check pins it)*
- `OS.IO.Poll/never` &mdash; [`OS_IO.Poll`](sig/OS_IO.md#exn-poll). It is never raised: the operating system is asked about every event, and answers when `poll` is called. *(no check pins it)*
- `OS.Path/unix-syntax` &mdash; [`OS_PATH`](sig/OS_PATH.md). Rune's paths are Unix paths: the separator is `/`, the only volume is the empty string, and `fromUnixPath` and `toUnixPath` are the identity.
- `OS.Path.InvalidArc/what-is-invalid` &mdash; [`OS_PATH.InvalidArc`](sig/OS_PATH.md#exn-invalidarc). On Unix an arc is invalid exactly when it contains a `/`. *(no check pins it)*
- `OS.Process.status/of-a-command` &mdash; [`OS_PROCESS.status`](sig/OS_PROCESS.md#type-status). The status of a command that `system` ran is its exit code, or 256 plus the number of the signal that ended it, which [`Posix.Process.fromStatus`](sig/POSIX_PROCESS.md#val-fromstatus) decodes. *(no check pins it)*
- `OS.Process.atExit/how-actions-run` &mdash; [`OS_PROCESS.atExit`](sig/OS_PROCESS.md#val-atexit). The actions run in the reverse of the order they were given in, at a normal end and at `exit` but not at `terminate` and not after an uncaught exception. The exception of an action that raises is dropped and the others run, and an action that calls `atExit` registers nothing. *(no check pins it)*
- `PackReal/encodings` &mdash; [`PACK_REAL`](sig/PACK_REAL.md). `PackReal` and `PackReal64` write the 8 bytes of binary64; `PackReal32` the 4 bytes of binary32, and a NaN becomes the quiet NaN of its sign, so a payload is lost. *(no check pins it)*
- `PackWord/sizes` &mdash; [`PACK_WORD`](sig/PACK_WORD.md). The library has `PackWord16`, `PackWord32` and `PackWord64`, each `Big` and `Little`. *(no check pins it)*
- `Posix.ProcEnv/what-a-check-can-expect` &mdash; [`POSIX_PROC_ENV`](sig/POSIX_PROC_ENV.md). What these report is whatever `id`, `uname`, `date` and `getconf` report on the machine, so that is what the suite compares them with. The test runner gives every program `/dev/null` for its standard input, so no descriptor a check sees is a terminal.
- `Posix.ProcEnv.getgroups/compared-with-id-G` &mdash; [`POSIX_PROC_ENV.getgroups`](sig/POSIX_PROC_ENV.md#val-getgroups). The suite compares the list with what `id -G` prints, which also lists the effective group, so that group is added before comparing.
- `Posix.Signal/numbers-are-the-systems` &mdash; [`POSIX_SIGNAL`](sig/POSIX_SIGNAL.md). A signal is the number the system gives it, which differs from system to system; the suite checks each name against what the shell's `kill -l` calls that number. Signals that would dump core, stop the process or be ignored by the runner are checked by number only and never sent.
- `Posix.SysDB/what-a-check-can-assume` &mdash; [`POSIX_SYS_DB`](sig/POSIX_SYS_DB.md). The suite assumes that the user and the group numbered 0 exist and are called `root`, which holds on Linux and the BSDs, and compares the other fields with what `getent` prints.
- `String.string/bytes` &mdash; [`STRING.string`](sig/STRING.md#type-string). [`String.string`](sig/STRING.md#type-string) is the top-level `string`, a sequence of 8-bit characters; [`WideString.string`](sig/STRING.md#type-string) is one of [`WideChar.char`](sig/CHAR.md#type-char). *(no check pins it)*
- `String.string/u-escape-above-255-rejected` &mdash; [`STRING.string`](sig/STRING.md#type-string). An escape `\uXXXX` above 255 in a constant of type `string` or `char` is an error when the program is compiled, for the characters have eight bits; at [`WideString.string`](sig/STRING.md#type-string) it is a character. *(no check pins it)*
- `String.maxSize/value` &mdash; [`STRING.maxSize`](sig/STRING.md#val-maxsize). 1073741823, which is 2^30 - 1.
- `String.maxSize/Size-is-not-pinned` &mdash; [`STRING.maxSize`](sig/STRING.md#val-maxsize). With a bound of 2^30 \- 1 no check of the suite makes a string that is too long: [`Size`](sig/GENERAL.md#exn-size) from [`^`](sig/STRING.md#val-op-caret), [`concat`](sig/STRING.md#val-concat), [`implode`](sig/STRING.md#val-implode) and `translate` is raised by the VM when the bound is passed, and the suite checks it only on a system whose `maxSize` is at most 2^26. The same holds for [`StringCvt.padLeft`](sig/STRING_CVT.md#val-padleft) and `padRight`, for [`Substring.concat`](sig/SUBSTRING.md#val-concat) and `concatWith`, and with [`Vector.maxLen`](sig/VECTOR.md#val-maxlen) for [`Vector.concat`](sig/VECTOR.md#val-concat) and [`VectorSlice.concat`](sig/VECTOR_SLICE.md#val-concat). *(no check pins it)*
- `Substring.substring/slice` &mdash; [`SUBSTRING.substring`](sig/SUBSTRING.md#val-substring). It is [`CharVectorSlice.slice`](sig/MONO_VECTOR_SLICE.md#val-slice), the slice of a vector of characters, so the two structures describe one type. *(no check pins it)*
- `Substring.extract/no-overflow` &mdash; [`SUBSTRING.extract`](sig/SUBSTRING.md#val-extract). The bounds are tested so that they cannot overflow: an `i` and an `n` whose sum is no `int` raise [`Subscript`](sig/GENERAL.md#exn-subscript), not [`Overflow`](sig/GENERAL.md#exn-overflow). *(no check pins it)*
- `Timer.checkCPUTimes/gc-from-the-collector` &mdash; [`TIMER.checkCPUTimes`](sig/TIMER.md#val-checkcputimes). The VM adds up the processor time of every collection, user and system apart, and `gc` is how much of that has passed since the timer started; `nongc` is the rest. A collection that grows the heap counts once.
- `Timer.checkGCTime/user-time-of-the-collections` &mdash; [`TIMER.checkGCTime`](sig/TIMER.md#val-checkgctime). It is the `usr` field of what `checkCPUTimes` reports under `gc`; the system time of a collection is in that record and not here.
- `Timer.totalCPUTimer/from-process-start` &mdash; [`TIMER.totalCPUTimer`](sig/TIMER.md#val-totalcputimer). The "system-dependent initialization time" is the start of the process, so the timer's base is zero processor time and what it reports is what the whole run has used. *(no check pins it)*
- `Timer.totalRealTimer/from-initialisation` &mdash; [`TIMER.totalRealTimer`](sig/TIMER.md#val-totalrealtimer). It counts from the moment the library was initialised, just before the program's own code begins. *(no check pins it)*
- `Vector.maxLen/value` &mdash; [`VECTOR.maxLen`](sig/VECTOR.md#val-maxlen). 100000000; an array has the same bound. *(no check pins it)*
- `Posix.TTY/what-the-values-are` &mdash; [`POSIX_TTY`](sig/POSIX_TTY.md). A set of flags is a `tcflag_t` word of the system, a speed is its `speed_t`, and the control characters are a string of `V.nccs` characters; all of them are read and written in one call. *(no check pins it)*
- `Posix.TTY.speed/is-speed_t` &mdash; [`POSIX_TTY.speed`](sig/POSIX_TTY.md#type-speed). It is the system's `speed_t`, and the named speeds are ordered by their baud rate. *(no check pins it)*
- `Posix.IO.FLock/is-a-flock` &mdash; [`POSIX_IO.FLock`](sig/POSIX_IO.md#str-flock). The lock operations are `fcntl` with a `struct flock`, and a `flock` here is that record. *(no check pins it)*
- `Posix.IO.mkBinReader/positions` &mdash; [`POSIX_IO.mkBinReader`](sig/POSIX_IO.md#val-mkbinreader). Only a regular file has positions, so `getPos`, `setPos`, `endPos` and `verifyPos` are `NONE` for a pipe, a socket or a terminal.
- `Real.real/binary64` &mdash; [`REAL`](sig/REAL.md). [`Real.real`](sig/REAL.md#type-real) is the top-level [`real`](sig/REAL.md#val-fromint), the 64-bit IEEE double (`radix` 2, `precision` 53\), and so are [`LargeReal`](sig/REAL.md) and [`Real64`](sig/REAL.md); the optional [`Real32`](sig/REAL.md) is binary32. The conversions to and from text are correctly rounded, through the C library. *(no check pins it)*
- `Real.precision/double` &mdash; [`REAL.precision`](sig/REAL.md#val-precision). 53 for binary64, which is 52 stored bits and the leading one that is not stored. The arithmetic must show that precision and no more: `1.0 + 2^~52` is greater than `1.0`, and `1.0 + 2^~53` rounds back to `1.0`.
- `Real.*+/fused` &mdash; [`REAL.*+`](sig/REAL.md#val-op-star-plus). Whether the multiplication and the addition are rounded once or twice is left to the implementation. *(no check pins it)*
- `Real.floor/at-the-ends-of-int` &mdash; [`REAL.floor`](sig/REAL.md#val-floor). An `int` has 64 bits and a real 53, so near the ends of `int` not every integer is a real. `fromInt maxInt` is 2^63, which is one more than `maxInt`, and [`floor`](sig/REAL.md#val-floor) of it raises [`Overflow`](sig/GENERAL.md#exn-overflow); the largest real that [`floor`](sig/REAL.md#val-floor), [`ceil`](sig/REAL.md#val-ceil), [`trunc`](sig/REAL.md#val-trunc) and [`round`](sig/REAL.md#val-round) take is 2^63 - 1024. `minInt` is a real, and `minInt - 0.5` is `minInt` itself, so all four give `minInt` for it.
- `OS.errorName/posix-names` &mdash; [`OS.errorName`](sig/OS.md#val-errorname). The names are those of [`Posix.Error`](sig/POSIX.md#str-error), lower case and without the `E`: `"noent"` rather than `"ENOENT"`. An error that POSIX has no name for is called `error` and its number, `"error9999"`, which `syserror` reads back.
- `TextIO.output/no-translation` &mdash; [`TEXT_IO.output`](sig/TEXT_IO.md#val-output). On the POSIX systems the suite runs on, a text file holds exactly the characters written to it: no newline is translated and no character is dropped, for all 256 of them.
- `TextIO.openOut/buffer-mode` &mdash; [`TEXT_IO.openOut`](sig/TEXT_IO.md#val-openout). The mode is `LINE_BUF` when the file is a terminal and `BLOCK_BUF` otherwise, as the specification asks; but the stream itself holds nothing back. The VM keeps the block and flushes every file at exit, so what a program writes with `print` and what it writes through a stream reach the file in the order it wrote them. *(no check pins it)*
- `Unix.executeInEnv/exec-failure-is-126` &mdash; [`UNIX.executeInEnv`](sig/UNIX.md#val-executeinenv). A child whose `exec` fails ends with the status 126, as the page asks; that is what a `reap` of it reports, rather than an exception in the parent. On Windows, which starts a program without a child of this one's and knows at once that it cannot be run, this raises [`OS.SysErr`](sig/OS.md#exn-syserr), which the page allows as well.
- `SOCKET/ipv6-is-a-family-of-the-system` &mdash; [`SOCKET`](sig/SOCKET.md). The page names no address family: "AF.list returns a list of all the available address families", so the set is the system's. `INET6` is among them here, and [`INET6_SOCK`](sig/INET6_SOCK.md), which is Rune's own, has the sockets and addresses of it; [`NetHostDB`](sig/NET_HOST_DB.md) stays the IPv4 database the specification defines *(no check pins it)*
- `Socket.sock/is-a-descriptor` &mdash; [`SOCKET`](sig/SOCKET.md). A socket is the system's descriptor and a `sock_addr` the bytes of a `sockaddr`; the type variables are phantoms and hold nothing. The `NB` forms put the descriptor into non-blocking mode for the call and back afterwards. Sending to a peer that has gone fails with the condition `pipe` rather than raising the signal of that name. *(no check pins it)*
- `Socket.Ctl/defaults-are-the-systems` &mdash; [`SOCKET.Ctl`](sig/SOCKET.md#str-ctl). The values a new socket starts with are those of the C socket interface, which has every flag here off. The suite sets `DEBUG` to `false` only, since turning it on needs privileges.
- `Socket.Ctl.getLINGER/whole-seconds` &mdash; [`SOCKET.Ctl.getLINGER`](sig/SOCKET.md#val-ctl.getlinger). The system keeps the time in a `struct linger`, in whole seconds. *(no check pins it)*
- `Socket.Ctl.setSNDBUF/at-least` &mdash; [`SOCKET.Ctl.setSNDBUF`](sig/SOCKET.md#val-ctl.setsndbuf). The system may give more room than was asked for -- Linux doubles it -- so the size read back is only bound to be at least `n`.
- `Socket.Ctl.getATMARK/the-last-byte-is-urgent` &mdash; [`SOCKET.Ctl.getATMARK`](sig/SOCKET.md#val-ctl.getatmark). The mark falls where the host's TCP puts it: sending `"abc"` out of band puts it after `"ab"`, the last byte being the urgent one.
- `Socket.select/is-poll` &mdash; [`SOCKET.select`](sig/SOCKET.md#val-select). It is [`OS.IO.poll`](sig/OS_IO.md#val-poll), so a negative timeout is refused rather than taken to mean "no timeout". *(no check pins it)*
- `Posix.Process.fromStatus/status-encoding` &mdash; [`POSIX_PROCESS.fromStatus`](sig/POSIX_PROCESS.md#val-fromstatus). An [`OS.Process.status`](sig/OS_PROCESS.md#type-status) is an `int`: the exit code of a process that ended of itself, 256 and the number of the signal that ended it, or 512 and the number of the signal that stopped it.
- `Posix.Process.W/only-untraced` &mdash; [`POSIX_PROCESS.W.untraced`](sig/POSIX_PROCESS.md#val-w.untraced). It is the only flag here; the `WNOHANG` of POSIX is what `waitpid_nh` is, and is added by that function itself.
- `Posix.FileSys.stdin/is-0` &mdash; [`POSIX_FILE_SYS.stdin`](sig/POSIX_FILE_SYS.md#val-stdin). The three standard descriptors are the words 0, 1 and 2, which POSIX fixes and the page does not state.
- `Posix.FileSys.S/values-of-the-C-binding` &mdash; [`POSIX_FILE_SYS.S.irwxu`](sig/POSIX_FILE_SYS.md#val-s.irwxu). The bits are the ones of the system's `<sys/stat.h>`: `irwxu` is 0700 through `isuid` 04000 and `isgid` 02000, and `all` is 07777, every bit that `chmod` sets, the sticky bit included.
- `Posix.FileSys.S.isgid/may-not-stick` &mdash; [`POSIX_FILE_SYS.S.isgid`](sig/POSIX_FILE_SYS.md#val-s.isgid). The owner may always set `isuid`; `isgid` is only bound to stay set when the file's group is one of the process's own groups.
- `Posix.FileSys.mkdir/shares-OS.FileSys` &mdash; [`POSIX_FILE_SYS.mkdir`](sig/POSIX_FILE_SYS.md#val-mkdir). `rmdir`, `chdir`, `getcwd`, `unlink`, `rename`, `readlink`, the directory streams and `access` are the functions of [`OS.FileSys`](sig/OS.md#str-filesys) under the names of POSIX, and `mkdir` differs from [`OS.FileSys.mkDir`](sig/OS_FILE_SYS.md#val-mkdir) in the mode only. *(no check pins it)*
- `Posix.FileSys.ST.atime/whole-seconds` &mdash; [`POSIX_FILE_SYS.ST.atime`](sig/POSIX_FILE_SYS.md#val-st.atime). The three times are kept in whole seconds, so they have no fraction. *(no check pins it)*
- `Posix.FileSys.chown/only-what-is-allowed` &mdash; [`POSIX_FILE_SYS.chown`](sig/POSIX_FILE_SYS.md#val-chown). An unprivileged process may not give a file away, so the suite only checks setting the owner and group a file already has.
- `Posix.FileSys.pathconf/what-a-check-can-assume` &mdash; [`POSIX_FILE_SYS.pathconf`](sig/POSIX_FILE_SYS.md#val-pathconf). The suite asks that `NAME_MAX` be bounded and lie between 13 and 255, and allows `PATH_MAX` and `LINK_MAX` to be unbounded, `PATH_MAX` being at most 65535 when it is not.
- `Posix.Error.errorName/the-posix-names` &mdash; [`POSIX_ERROR.errorName`](sig/POSIX_ERROR.md#val-errorname). For the conditions POSIX names it is the name below -- `"noent"` for `noent` \-- and for the others it is the name [`OS.errorName`](sig/OS.md#val-errorname) invents. *(no check pins it)*
- `Posix.Error.acces/not-for-the-superuser` &mdash; [`POSIX_ERROR.acces`](sig/POSIX_ERROR.md#val-acces). Permission bits do not stop a privileged process, so the suite's checks of this and of `perm` hold for an ordinary user and pass trivially as root.
- `Posix.Error.inval/rename-into-itself` &mdash; [`POSIX_ERROR.inval`](sig/POSIX_ERROR.md#val-inval). Renaming a directory into itself is taken to report this condition.
- `Real32.real/binary32-in-a-double` &mdash; [`REAL`](sig/REAL.md), in `Real32`. A [`Real32.real`](sig/REAL.md#type-real) is kept as a binary64 whose value is one of binary32: an operation computes in binary64 and rounds what it gets to binary32, in the rounding mode that is set. That is the correctly rounded result for `+`, `-`, `*`, `/` and `sqrt`; `*+` and `*-` round twice. The type is abstract and is not [`real`](sig/REAL.md#val-fromint), and a real constant at this type is rounded once, as C's `strtof` reads it. *(no check pins it)*
- `WideChar.toString/escapes-above-255` &mdash; [`CHAR`](sig/CHAR.md), in `WideChar`. `toString` and `toCString` write a character above 255 as `\uXXXX`, or `\UXXXXXXXX` above 0xFFFF, as MLton writes them, and `fromString` and `fromCString` read those escapes. `fromString` also reads `\ddd` of exactly three decimal digits, and `fromCString` the escapes of C, whose digits are octal; an octal or a `\x` escape of C names a character up to 255 only, so that `fromCString "\\x1F600"` is `NONE`. The text they take and give is of `char`, the 8-bit one, as the signature writes it, and `scan` reads from a stream of `char` and yields a wide character.
- `WideTextIO/files-hold-utf-8` &mdash; [`PRIM_IO`](sig/PRIM_IO.md), in `WideTextPrimIO`. The specification names no encoding, so a stream of `WideTextIO` is a stream of [`TextIO`](sig/TEXT_IO.md) encoded in UTF-8: one byte for a code point below 128, up to four above it. A byte sequence that is not UTF-8 raises [`IO.Io`](sig/IO.md#exn-io) with the cause `Fail "UTF-8"`. A stream made with `mkInstream` over a reader of one's own carries wide characters as they are, without an encoding. No host has a `WideTextIO` to compare with.

## Limitations

What is missing or only partly there.

- `SML90/is-history` &mdash; [`SML90`](sig/SML90.md). The page that defined this signature is no longer among the specification's pages; it is transcribed from MLton's library, which follows it, in the order the page had. *(no check pins it)*
- `SML90.Interrupt/never-raised` &mdash; [`SML90.Interrupt`](sig/SML90.md#exn-interrupt). It is declared and nothing raises it: the VM handles no signal, so an interrupt ends the program. *(no check pins it)*
- `WideTextIO/file-streams-have-no-positions` &mdash; [`PRIM_IO`](sig/PRIM_IO.md), in `WideTextPrimIO`. The reader and the writer of a file of wide characters have no positions, no `ioDesc`, no operations that do not block, and neither `canInput` nor `avail`: a position in the file is one of bytes and not of characters. Their `chunkSize` is 1024 characters, where a file of [`TextIO`](sig/TEXT_IO.md) has 4096.

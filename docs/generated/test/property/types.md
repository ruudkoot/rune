# Types that are one type

[Property testing](README.md)

Types with several names: a value of one is a value of the others, and a function on one takes
them all. They are found by elaborating the library and comparing the type names, so the table
says what is the case and not only what is meant. A type that abbreviates more than a name, such
as a reader or a record, is not listed. Every name says why it is a name of its type:

- **required by the signature** (32): the signature of the structure, with the `where type`
  of its declaration in the specification, says which type it is, as `CharVector.vector` is `string`;
- **required of the top level** (0): the top level is defined to have the type of that
  structure, as `int` is `Int.int`;
- **the implementation's choice** (0): the structure is another structure by name, which the
  specification leaves open, as `Position` is `Int` here; a program that relies on it is not portable;
- **abstract in the specification** (0): nothing says which type it is, and the library shows
  what it is made of. A program that relies on it is not portable, and the type checker of another
  system rejects it. There should be none of these.

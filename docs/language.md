# The Rune language

Rune compiles **Standard ML '97** (the full Core and Modules language of *The
Definition of Standard ML (Revised)*, and the Basis Library subset listed
below) to bytecode for the `runevm` interpreter. This document is the authoritative description of what Rune
accepts; `make check-docs` verifies that every feature marked *Supported* or
*Partial* has a test in `tests/lang/` named `<id>_<something>.sml`, and that
every test corresponds to a row here.

Status values: **Supported** (implemented, tested), **Partial** (implemented
with documented restrictions), **Planned** (not yet implemented; using it is a
compile-time error). The order in which the *Planned* rows and the deviations
below are to be closed is in [plans/sml97.md](plans/sml97.md).

## Deviations from the Definition

These are the choices the Definition leaves to an implementation, plus the
few places where Rune knowingly departs from it. They never make a well-typed
SML program behave differently; they only make Rune accept some programs that
SML rejects, or reject some that SML accepts.

| Topic | Rune behaviour |
|---|---|
| Integer literals | An integer constant is overloaded over the types of kind `int` and defaults to `int`; a word constant likewise over the kind `word`. Besides `int` and `word` these are `Int64.int` (= `FixedInt.int`) and `Word64.word` (= `LargeWord.word`), which the compiler knows as it knows `int` and `word`, and the types the basis library registers with `_overload`: `IntInf.int` (= `LargeInt.int`), `Int8.int`, `Int16.int`, `Int32.int`, `Word8.word`, `Word16.word` and `Word32.word`. A constant that its type cannot represent is a compile-time error (`int` and `word` have 63 bits, `Int64.int` and `Word64.word` 64). An `IntInf.int` constant is converted from its digits where it is evaluated, and compared structurally in a pattern. A real constant is overloaded likewise over the kind `real`, `real` and `Real32.real`, and defaults to `real`; a `Real32.real` constant is read to binary32 from its text where it is evaluated. Character and string constants are overloaded over the kinds `char` and `string`, `char`/`string` and `WideChar.char`/`WideString.string`, and default to `char` and `string`; a code point above 255 (the escapes `\ddd`, `\uXXXX` and `\UXXXXXXXX`) is a compile-time error at the 8-bit types, and a wide constant is made once, from its text, when the top-level declaration that holds it runs, and not where it is evaluated. `Int` is 64-bit, `Word` is 64-bit, `Real` is IEEE double. |
| Strings | `string` and `char` are 8-bit, a byte a character; `WideString.string` and `WideChar.char` hold every code point. A character above 255, written `\ddd`, `\uXXXX` or `\UXXXXXXXX`, is a compile-time error at the 8-bit types and taken at the wide ones (*Integer literals* above), where `\ddd` goes up to 999 as the Definition's alphabet allows (Section 2.2). `\UXXXXXXXX` is an extension, from Successor ML, and is taken under `--unicode` only (`the escape \U needs --unicode`). A literal holds no raw control character, DEL included, as the Definition's printable characters are 33 to 126 and space: it is written as its escape (`\t`, `\127`). A raw character above 127 in a literal means its code point, as its escape does, in every mode that takes it ([units.md](units.md), *Source modes*): by default none is taken, and the character is written as its escape (`\u00E9`); under `--unicode` the wide types take it, and `char` and `string` refuse it, with the escapes that say the character or its UTF-8 (`\233`, `\195\169`); under `--unicode=latin1` it is the file's own byte at every type. A surrogate, U+D800 to U+DFFF, in `\u` or `\U` is an error at every type: a deviation, since the Definition's alphabet holds it (`tests/errors/err.lex_surrogate*`). Outside a literal or a comment a character above 127 is an error that names it (`unexpected character U+03BB`), or the byte where the text is not UTF-8, but in a name under `--unicode` (*Identifiers* below). |
| Source text | A source is read in a mode ([units.md](units.md), *Source modes*): its text is UTF-8, or Latin-1 under `--unicode=latin1`, and what it may hold raw is the same in every mode but in a literal (*Strings* above). Between tokens white space is space, TAB, LF, CR LF and FF (rows `lex.space`, `lex.bom`). The Definition allows any character in a comment; Rune refuses there, as everywhere, the controls but TAB, LF, CR LF and FF, DEL, the C1 controls (NEL among them), the line and paragraph separators U+2028 and U+2029, the nine explicit bidi controls (U+202A to U+202E, U+2066 to U+2069) of Trojan Source, a byte order mark past the start and text that is not UTF-8 (rows `lex.comments`, `lex.bidi`, `lex.encoding`). This is a deviation, pinned by `tests/errors/err.lex_comment_*` and `err.lex_trojan_*`; the marks LRM, RLM and ALM and the other default-ignorables stay allowed in comments and literals. |
| Identifiers | An alphanumeric identifier is ASCII by default, as the Definition has it (Section 2.4). Under `--unicode` (and `--unicode=latin1`) it may also hold the letters, marks and digits of the identifier profile of `lib/unicode` (`Identifier`): UAX #31's XID_Start and XID_Continue, less the default-ignorable characters and 239 lookalikes of Standard ML's punctuation and digits, frozen at Unicode 18.0.0. This is an extension, which Successor ML asks for (issue #33). A character the profile leaves out is refused with the reason, a default-ignorable character, which shows nothing, or a lookalike of the character it looks like (`the character U+01C3 in a name is a lookalike of !`), and so is the invisible identifier of Trojan Source, U+3164. A name is in NFC, and one that is not is refused with its NFC spelling (`write it as ...`), not converted, so that names are compared by their bytes (`tests/errors/err.lex_name_*`). Symbolic identifiers, record labels (`a record label is ASCII`) and numbers stay ASCII in every mode. The compiler warns of what UTS #39 finds suspect in a source's names: a character it restricts, a name that mixes scripts (each part between `_` and `'` judged by itself, beyond its moderately restrictive profile), a name that looks like another of the same source, and a name that looks like a reserved word or whose skeleton is Standard ML's punctuation (a lone `ノ` looks like `/`); and, in every mode, of a lookalike of `*)` in a comment, which does not end it (UTS #55). `--no-unicode-lints` turns these warnings off. A name the library exports is ASCII, so that a program in every mode can name it. |
| Functors | A functor body is specialised per application (the copy is type-checked against the actual argument, which cannot fail after the check against the parameter signature). This is not observable, but the bytecode contains one copy of the body per application. |
| Programs | Rune is a batch compiler: a static error in any top-level declaration rejects the whole program, and an uncaught exception terminates it. Chapter 8 regards programs as interactive and would skip the failing declaration and continue. A top-level declaration that fails to elaborate is reported, and skipped as Chapter 8 would, so that the declarations after it are elaborated too and every independent error of the program is reported before it is rejected ([units.md](units.md), *Errors*); a syntax error still ends the compile. |
| The REPL | `rune-repl` reads top-level declarations and runs each as Chapter 8 says: a declaration that does not elaborate is reported and leaves the session as it was; one whose running raises an exception binds nothing and keeps its effects; `exp;` binds `it`. `use file` (`Compiler.use`) runs the declarations of a file so, stopping at the first that fails. Every value a declaration binds is echoed with its type, by a printer made from the type. A matching visible `toString` formatter precedes generic datatype printing; `IntInf` values print as decimal integers through type aliases as well (`tests/repl/intinf.in`). Installed pretty printers retain priority. Ctrl-C ends the declaration running, as one that raised, and drops a line half typed ([repl.md](repl.md); `tests/repl`). |
| Overloading | Overloaded operators and literals are resolved (and defaulted) at the end of the enclosing top-level declaration. `~` is overloaded at `int`, `word` and `real`. `^`, `size`, `concat` and `substring` are overloaded over the class String, `string` and `WideString.string`, as the comparisons are, and default to `string` (row `ty.overload.string`): an extension of Appendix E, whose list of overloaded identifiers is closed. A program of Standard ML '97 keeps its types, by the default; `str`, `implode`, `explode` and `print` stay 8-bit. |
| Flexible records | The labels of a flexible record pattern (`{a, ...}`) or selector (`#a`) must be determined by the program context, whose size Section 4.11 leaves to the implementation; `rune --flex-records=MODE` chooses it. `topdec`, the default, is Poly/ML's and MLton's: the top-level declaration -- to a `;` or the end of the file -- and a generalised flexible record is determined by each of its uses, the types of the labels it did not mention per use. `topdec-monomorphic` is Moscow ML's: the same, but a flexible record is not generalised, so its uses must agree. `declaration` is MLKit's: the declaration at structure level it is in. `binding` is SML/NJ's and Hamlet's: the binding that would generalise it. `program` is the whole program (the unit, with `--units`), which Rune did before the option. In the modes of a top-level declaration, the free type variables of rules 87-89 are those left where the top-level declaration ends, and the REPL compiles and runs a top-level declaration at once ([repl.md](repl.md)); `tests/flexrec` holds each mode to what the implementation it follows did with the same programs. |
| `_prim "name" : ty` | Extension used by the basis library to access VM primitives. Only allowed with `--allow-prim`. |
| `structure X = _dynamic "path" : SIG` | Extension: a dynamic module, the unit at `path` loaded when the program reaches the declaration, compiled against `SIG` alone ([units.md](units.md), *Dynamic modules*). The program is built in units (`--units`). |
| `_export structure X : SIG = strexp` | Extension: a dynamic module's implementation, at the top level of a unit: `X` ascribed to `SIG` opaquely, each datatype that a datatype of `SIG` specifies given its constructors' tags in the signature's order, and its values and exceptions what the unit exports. |
| `structure X = _virtual : SIG` | Extension: a virtual module, compiled against `SIG` alone; its implementation is the structure `X` that a unit before it exports (`_export`), which the build file chooses ([build.md](build.md), *Virtual modules*). |
| `_overload kind Strid [bits \| via f]` | Extension used by the basis library: a declaration that makes the type `Strid.kind` (`kind` is `int`, `word`, `real`, `char` or `string`) an overloading type. The overloaded operators at that type are the values `Strid.+`, `Strid.<`, ...; its constants are those of the builtin type restricted to `bits` bits (default 64), or `f digits` for a function `f : string -> Strid.kind`. Only allowed with `--allow-prim`. |
| Or-patterns | `(p1 \| ... \| pn)` (row `pat.or`), an extension of Successor ML and SML/NJ. Only allowed with `--or-patterns`: without it Rune takes Standard ML '97 alone and rejects one. |
| Default types | `--default-type=int64` and `--default-type=word64` make an integer or word constant, or an operator of the classes Int or Word, that its declaration leaves open default to `Int64.int` or `Word64.word` instead of `int` or `word`, in the input files and not in the libraries (row `ty.overload.default`), as MLton's `-default-type` does. Without them Rune defaults as Appendix E says. |
| I/O | The imperative streams of `TextIO` and `BinIO` are datatypes rather than abstract types, so an `instream` (a reference) admits equality; an `outstream` does not. `CharVector.vector` is `string` (the specification requires it) and `Word8Vector.vector` is one underneath but abstract; a `Word8Array.array` and a `CharArray.array` are the VM's array of bytes, a byte an element. |

## Lexical structure

| ID | Feature | Status | Notes |
|---|---|---|---|
| lex.comments | Nested comments `(* ... (* ... *) ... *)`, holding any text | Supported | Unterminated comments are errors. A comment holds any UTF-8 text (Latin-1 under `--unicode=latin1`) in every mode but what *Source text* above refuses: a control but TAB, LF, CR LF and FF, DEL, a C1 control, U+2028, U+2029, an explicit bidi control, a byte order mark, and text that is not UTF-8 (`tests/errors/err.lex_comment_*`). A lookalike of `*)`, such as U+2217 before `)`, does not end a comment, and the compiler warns of it (`lex.comments_lookalike`). |
| lex.space | White space between tokens: space, TAB, LF, CR LF and FF | Supported | In every mode. A vertical tab, a CR not before a LF, and every other control are refused (`tests/errors/err.lex_space_*`); a string's gap holds the same white space (`err.lex_gap_*`). Lines end at LF, so CR LF is one line end. |
| lex.bom | A byte order mark at the start of a UTF-8 file | Supported | Dropped, as no part of the text; anywhere else it is refused (`tests/errors/err.lex_space_bom`, `err.lex_comment_bom`, `err.lex_string_bom`). Under `--unicode=latin1` its bytes are three characters of Latin-1. |
| lex.bidi | The explicit bidi controls, U+202A to U+202E and U+2066 to U+2069, refused everywhere; the marks LRM, RLM and ALM allowed in comments and literals | Supported | Trojan Source (Boucher and Anderson): its early return, its commenting out and its stretched string are each refused (`tests/errors/err.lex_trojan_*`); a literal writes a bidi control as an escape (`\u202E`). |
| lex.encoding | Source text in UTF-8, or in Latin-1 under `--unicode=latin1` | Supported | Text that is not UTF-8 is refused where it is met, in a comment and a literal too (`tests/errors/err.lex_comment_utf8`, `err.lex_string_utf8`); under `--unicode=latin1` the file is made UTF-8 as it is read, every byte the character of its number, a C1 control is refused, and a file that holds the UTF-8 of a character above 127 is refused as one that "looks like UTF-8" (`tests/errors/err.lex_latin1_*`). |
| lex.int | Integer literals: decimal, `~` negative, `0x` hexadecimal | Supported | An `int` is 63 bits, two's complement: the VM's word less the bit of its tag. A constant beyond them is a compile-time error. |
| lex.word | Word literals `0w...`, `0wx...` | Supported | A `word` is 63 bits. |
| lex.int64 | Integer and word literals at `Int64.int` and `Word64.word`, in expressions and patterns | Supported | 64 bits on every VM. Equality is of the number, whether the VM keeps it in a word or in a box. |
| lex.real | Real literals with `.`, `e`/`E` exponents and `~` signs | Supported | Not allowed in patterns. |
| lex.char | Character literals `#"c"` with all SML escapes | Supported | `\ddd`, `\uXXXX`, `\UXXXXXXXX` (under `--unicode`), `\^C`, `\a\b\t\n\v\f\r\\\"`; up to 255 at `char`, and any code point but a surrogate at `WideChar.char` (`\ddd` up to 999). A raw control character, DEL included, is an error; a raw character above 127 is taken as *Strings* above says. |
| lex.string | String literals with escapes and `\ whitespace \` gaps | Supported | The escapes of `lex.char`, up to 255 at `string` and any code point but a surrogate at `WideString.string`; a raw character above 127 by the mode, at the four types (`tests/lang/lex.string_modes_*`; *Strings* above). A raw control character, DEL included, is an error: it is written as its escape (`\t`, `\127`); so are the C1 controls, U+2028, U+2029, the bidi controls and a byte order mark (`\u202E`; *Source text* above). |
| lex.ident | Alphanumeric and symbolic identifiers, primes, `'a`/`''a` type variables, long identifiers `A.B.x` | Supported | All 50 reserved words including module keywords are reserved. Under `--unicode` a name may hold the letters, marks and digits of *Identifiers* above, in Greek, Cyrillic, CJK and Devanagari among other scripts (`lex.ident_unicode`), and the warnings of UTS #39 are pinned by `lex.ident_lint*`, with `--no-unicode-lints` and without. |

## Compiler resource budgets

Type traversal during elaboration is limited to 50000000 steps per top-level
declaration (`--type-work=N`), and so, apart, is the translation of each
top-level declaration's types (`type translation exceeds`), which the
elaborator keeps shared and the intermediate representations share too: a
type of 2^n nodes as a tree, as `f f ... f` of n applications makes, is
converted in steps that grow with n, not 2^n (about 6400 at 32
applications; docs/plans/type-checker.md); exhaustiveness and redundancy analysis is limited
to 1000000 steps per match (`--match-work=N`) and recursion depth 512. Both step
budgets can be raised with a positive decimal integer at most 1000000000. Exhausting a budget is a
source-located compile error, and preserves any previously generated bytecode.
Bytecode output is replaced atomically after a successful write. An output path
that names any explicit input, including a symlink or hard-link alias, is rejected.

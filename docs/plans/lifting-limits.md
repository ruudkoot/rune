- this is a draft roadmap to lift some limits in rune (e.g. basis library and runtime/vm)
  - please consider critically and object to anything you disagree with
- the equality-work and type-work options need to be raised to a default setting such that it does not need to be overrridden anywhere in the repo to make tests or builds pass (type-work already high enough? and equality-work to 1G? the reason for the equality-work limit is seems to be there mostly to catch bugs causing it to go in an infinite loop? we have found no such bugs and have hit the equality-work limit in production several times. so if on 32-bit the max object size is 1G then 1G of equality should not abort in all situations? maybe propose a better way for 64-bit machines. if equality work is set to e.g. heap size does that prevent false positives? or should be just remove the equality-work limit completely if we are sure there are no bugs?)
- in the sml basis library strings and arrays are limitted to 100M elements. this has proven to be an issue in production use. the limit needs to be raised as far as possible.
- another agent reviewing the limits found during production workloads suggested the vm/gc currently only supports large objects to just over 1G.
  - for 32-bit machines this seems reasonable, though if we can raised to closer to 2GB or 3GB nearly for free then then we should do so
  - for 64-bit machines this is a bottleneck and the limit should be raised to at least 1TB and if reasonably possible far larger
  - if possible the runtime and basis library should co-operate such that opartions exceeding the vm limits throw an sml exception (e.g. Size) that can be handled cleanly (w/o introducing soundness, security or other issues) instead of a hard runtime/vm abort.
    - this should be a general pattern: runtime resource limit contraints should be turned into sml exceptions that the program can choose to catch and handle (as long as this can be done soundly and w/o security or other issues) and only e.g. bugs or malformed bytecode should result in a hard runtime/vm abort.

- this is a draft roadmap for runespec: a specification language for rune
- goals of runespec are:
  - generation of a latex/pdf resembling the "Definition of Standard ML (Revised)" from the specification
    - https://smlfamily.github.io/sml97-defn.pdf
    - https://people.mpi-sws.org/~rossberg/papers/sml-defects-2013-09-18.pdf (errata)
  - generation of language definitions in target theorem prover languages (e.g. lean, coq, isabelle)
  - generation of reference parsers from the specification
  - generation of a reference type checker / interpreter from the specification of the static / dynamic 
    - generation of derivation trees of the static and dynamic semantics
  - handle the full definition of standard ml (syntax, static and dynamic semantics of the Core and Module languages)
  - handle plausible extensions of standard ml likely to be introduced in rune (e.g. applicative and higher-order functions, lazy evaluation, type-and-effect system)
  - act as an oracle for the language tests under tests/lang
- bonus points if runespec is also capable of specifying itself in addition to standard ml
- non-goals of runespec are:
  - stating and proving metatheorems of rune (e.g. "well-typed programs do not go wrong")
  - stating and proving the metatheorems of rune will be done in the target languages of rune (e.g. lean, coq, isabelle) on top of the language definitions generated by runespec.
  - generation of production-grade parsers that can be used directly in the rune compiler
  - generation of a production-grade a type checker and interpreter that can be used directly in the rune compiler
- runespec is to written in standard ml / rune.
- the syntax of runespec specifications should be optimized for readability and evaluation correctness of the specification.
  - if should deal gracefully with the requirements of specifying standard ml (e.g. dealing with fresh names?)
  - where the previous allows for choice the syntax of runespec specification should resemble standard ml 
- runespec should be elegent in the sense that it includes no more features than required to achieve its goals and includes all features required to state the specification clearly and directly

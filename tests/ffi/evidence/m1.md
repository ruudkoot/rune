# M1 frontend acceptance — 2026-10-22

Implementation follows M0 commit `1a4f260c0` in the isolated `runeffi`
worktree. The reusable `lib/language/c` library contains preprocessing
tokens and physical locations, macro expansion origins, explicit-width
integer folding, typedef-sensitive declaration parsing, enum folding and
original-byte include resolution. The development driver is
`bin/rune-cfrontend`; independent compiler comparisons are coordinated by
`bin/rune-c-check`, both implemented in SML.

## Scope and independent comparisons

The parser preserves arrays, function pointers, struct/union fields,
bit widths, enums, qualifiers, calling conventions, compiler attributes,
packing and balanced inline bodies. It does not compile C statements.
Preprocessing covers trigraphs/splicing, comments and literals, guarded and
recursive includes, `include_next`, object/function/variadic macros,
rescanning, stringification, token pasting, conditionals, source builtins,
`_Pragma`/`__pragma`, packing, and macro push/pop. Unsupported active
syntax/directives produce diagnostics rather than modified headers.

Integer folding uses explicit intmax/uintmax widths with checked signed
overflow, unsigned wrapping and lazy conditional/logical arithmetic.
Identifiers/literal types are validated even in unevaluated operands.
The enum consumer handles implicit successors and rejects forward or
cyclic references. Layout-dependent expressions and typed casts belong to
M4; they are retained by the declaration parser and rejected if requested
from the integer-only folder. Long double, complex and vector ABI support
is not claimed by parsing a declaration.

`make test-c-frontend` compares the regression macro fixture with an
independent C preprocessor, and unchanged SDL headers with Clang 18.1.3.
`make test-c-frontend-windows` compares both unchanged delivery entrypoints
on both Microsoft profiles. Comparisons cover all preprocessing tokens and
packing directives, selected function arity/variadic shape in Clang's AST,
and all selected constants' integer values. Diagnostic/linker pragmas are
retained by Rune but omitted from token comparison because Clang consumes
some of them. They are not removed from Rune's model.

The profiles explicitly pin compiler capabilities and C11 predefinitions,
including Clang-compatible GNU feature values on Linux and MSVC 19.40
values on Windows. The independent AST check caught a missing
`_INTEGRAL_MAX_BITS=64`: without it the x86 SDK selected its historical
`double` fallback for `LONGLONG`. Both Windows profiles now specify it and
the reference translation unit asserts that `LONGLONG` is integral.
Original SDK and SDL bytes remain unchanged.

## Shared heap repair discovered by this work

Clang's full SDL/x86 AST is about 135 MiB. Parsing it exposed a pre-existing
large-object layout fault: proportional metadata pushed an object's header
past the first 2 MiB, violating `chunk_of`'s ownership mask. ASan found the
collector scanning metadata as object fields. A separate 64 MiB language
regression reproduces the invariant failure without the SDK or Clang.

The repair keeps cards/dirty bytes before very large payloads and places
other tables after their usable capacity. Copying-space dedicated runs are
closed at the object boundary. The regression passes with heap checking
on stack/register VMs, sanitizer VMs and `--nursery 0`. The original
frontend case passes ASan/UBSan after the fix. A redundant full-heap-check
run over the entire 135 MiB AST was stopped after 22 minutes; it is not
recorded as passed. The reduced regression supplies that verification.

## Repository acceptance

`make check matrix-quick windows portability JOBS=8` completed the full
repository run and host matrix. The full run recorded **19,379 PASS**, three
known skips and one host-adapter inventory guard failure out of **19,383**
cases. The corrected guard passed its focused **6/6** rerun. The matrix
recorded **3,182 PASS** and **156 SKIP** out of **3,338** cases, with no failures;
its skips are the existing unsupported host extensions. Windows and
portability builds also passed.

The new large-object regression passed native Windows x86/x86-64 and
Linux x86, PPC64 and AArch64, each with heap verification. The original
SDK/frontend case passed ASan/UBSan after the shared heap repair. This
milestone's checks do not establish FFI callbacks or generated GUI bindings.

The initial SDL manifest also accidentally selected deferred `SDL_RunApp`
integration. It is now explicitly deferred; the agreed inventory is 53
core SDL functions and 38 Win32 functions. Earlier 54-function results are
historical supersets. The final source guard rejects selecting that deferred
entry.
Final `make test-ffi-contracts test-c-frontend check-docs JOBS=8` passed
8/8, 7/7 and 11/11 cases. The original-header and pinned-host selection
passed 16/16 after the heap repair. That repair is committed separately
as `2dea043b3`; neither it nor the frontend adds per-function primitives.

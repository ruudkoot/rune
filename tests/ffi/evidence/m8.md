# Native Win32 component evidence — 2026-10-23

The selected 38-function native kernel/user/GDI implementation is complete.
M8 remains planned until the cumulative repository, Windows, portability,
host and release gates are recorded after integration. Public types and
signatures remain shared with SDL and mocks through `Win32Common.Types`.

## Architecture and artifacts

- `ffi/win32/core.ffi` reviews the original declarations' names, directions,
  ownership, nullability, lengths, output values, errors and retained
  callbacks. All selected declarations use the explicit
  `win32-native-v1` facade adapter; unsafe raw fallback is disabled.
- `lib/ffi/win32/native` implements the complete agreed `WIN32` signature
  with ordinary SML over the generic bridge, generated descriptors and
  typed field shims. It adds no primitive or function-specific runtime entry.
- The native facade handles creation-time identities, nested calls and
  destruction, callback exceptions with owned-result cleanup, message-copy
  disposal, paint scopes, GDI selection guards and captured native errors.
- `native-support.json` records the exact messages, styles, graphics,
  lifecycle rules, implementation limits and available execution modes.
- The SML coordinator `bin/rune-win32-check` owns explicit regeneration,
  native compilation and validation. Build entrypoints contain sources and
  virtual implementations; they never execute commands.

## Validation

Commands run with the pinned external include roots configured:

```sh
make bin/runeffi bin/rune-win32-check
bin/rune-win32-check generate 32 ffi/win32/generated/32
bin/rune-win32-check generate 64 ffi/win32/generated/64
bin/rune-win32-check contract 32
bin/rune-win32-check contract 64
bin/rune-win32-check app 32
bin/rune-win32-check app 64
make docs check-docs
```

Results:

- Both widths passed the exact shared 11-group contract in stack and register
  interpretation. x64 also passed forced baseline and optimizing JIT runs
  (`--jit-calls=1`); all shared runs use GC stress 101 and heap verification.
  x86 has no JIT backend and is explicitly reported unavailable, rather than
  treating interpreter fallback as JIT coverage.
- The focused native suite passed 37 checks in both instruction sets on both
  widths under GC stress 7 and heap verification. An additional forced x64
  optimizing JIT run passed the same 37 checks.
- Native-only regressions cover creation before return; non-null owned
  creation results after a callback exception; creation vetoes; destruction
  exceptions; active-class guards after nested destruction; unrelated class
  unregistration; Timer→SendClose→Destroy→Default; retryable EndPaint
  failures; preservation of the body exception; and MSG release when Quit
  conversion fails. Every suite verifies zero remaining native resources.
- Both widths passed original-SDK native C oracles for the eight integer
  helpers and a legitimate empty paint region. `paint-empty.c` validates the
  window, sends an internal `WM_PAINT`, calls BeginPaint inside WNDPROC and
  confirms an empty rectangle. This does not infer the exact cause of the
  earlier shared test's empty rectangle. Microsoft's
  [window-region contract](https://learn.microsoft.com/en-us/windows/win32/gdi/window-regions)
  explains clipping, and the
  [BeginPaint contract](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-beginpaint)
  specifies the message context and pairing.
- The unchanged `examples/win32/app.sml` passed native smoke execution on both
  widths and both interpreters; x64 also passed both forced JIT tiers.
  It opens a real window, draws through GDI and closes after three timer
  ticks. The same source is used by the SDL/mock provider component
  `4ca739d55`.
- Every acceptance mode regenerated twice and matched immutable identities.
  Strict `runeffi check` with the same target/include/layout/field/constant
  arguments also passed for both committed generation sets.
  Structured command receipts, toolchain version output, child stdout and
  stderr are retained in the coordinator's run directory.
- Documentation generation and all 11 consistency checks passed.

Initial receipts are preserved separately: an overly strong positive-paint
assertion failed on both widths and was corrected in shared fixture
`fd7bfb770`; a coordinator marker incorrectly looked for a stderr summary
on stdout; and a WSL launch initially omitted the adapter environment bridge.
The unchanged application then exposed a real native dispatch bug: returning
Default after synchronously closing its window attempted DefWindowProc on a
retired token (error 1400). Dispatch now returns the message-specific failure
value in that case, with an explicit regression. Those earlier receipts are
not described as clean full runs.

# M5 component evidence — 2026-10-23

The callback and opaque-handle component is implemented. M5 remains planned
until the repository-wide VM, Windows, portability and host acceptance gates
are recorded after integration.

## Implementation

- Generic libffi closures with VM-handle roots and explicit release.
- Owner-thread entry guards, synchronous native-call guards, and a maximum
  of 64 nested VM callback scopes. Callback arenas scale with actual arity
  instead of reserving maximum-sized C arrays at every nested entry.
- A bounded plain-interpreter delimiter for stack, register, JIT callers and
  `runeopt`; no recursive driver entry or JIT compilation/page mutation.
- Saved parked-native live masks for full/minor GC, with safepoint addresses
  restored by indices after stack/frame relocation.
- Trusted SML exception containment, argument-dependent native failure
  values and post-native-return propagation. WNDPROC-shaped failure policies
  distinguish `WM_NCCREATE`, `WM_CREATE` and other messages.
- Temporary callback pointer identities and their views expire on return.
- Canonical opaque handle adoption, including creation-time callbacks;
  nested handle consumption retires every alias after native success while
  strict memory disposal remains guarded. Nested destruction callbacks may
  use the handle; recursive consumption rejects.
- Callback instruction counts are preserved by the parked engines.

The exact contract and the driver exception are in
[docs/ffi/callbacks.md](../../../docs/ffi/callbacks.md).

## Focused acceptance

Toolchains: Ubuntu GCC 13.3.0; libffi 3.4.6; MinGW-w64 GCC 13-win32 for both
Windows widths; the pinned libffi 3.4.6 Windows static archives prepared in
the runtime acceptance worktree.

Commands run from the callback worktree:

```sh
make isa
make all
make windows FFI_WIN64_PREFIX=<checked-win64-prefix> FFI_WIN32_PREFIX=<checked-win32-prefix>
bin/rune-ffi-check runtime native
make vm-asan
bin/rune-ffi-check runtime asan
make docs
make check-docs
```

Results:

- The complete native FFI gate passed: existing scalar/pointer, memory,
  disposal and lifecycle fixtures, plus callbacks in stack/register
  interpretation, JIT tier 1/tier 2, and `runeopt`.
- The complete FFI ASan/UBSan gate passed, including callback fixtures with
  `--gc-stress 7 --gc-verify`. The sandbox's initial sanitizer doctor probe
  failed because LeakSanitizer cannot inspect traced threads there; the
  unrestricted build and run passed. No package was missing or installed.
- The native C callback oracle passed 15 allocation, release and native
  thread checks, including deterministic callback-creation allocation
  failures and refusal to execute SML on another native thread.
- The final shared callback fixture passed on Windows x86 and x86-64 stack
  and register VMs; x86-64 register execution used JIT tier 2. It covers
  stdcall message signatures and the depth-64 guard with Windows' default C
  stack.
- Callback collection and 6000-deep value-stack growth passed while a
  native/JIT caller was suspended. Active callback release, borrowed-view
  expiry, saved exceptions, native-thread failure tables, creation-time
  handles, nested destruction and recursive-destruction refusal passed.
- Paired final callback counts agree exactly: stack interpreter and
  `runeopt` each report 717350 instructions, 609096 bytes and 27912 objects;
  register interpreter and JIT tiers 1/2 each report 398547 instructions,
  594184 bytes and 27462 objects.
- The public-library qsort language fixture passed.
- Generated documentation was refreshed and `check-docs` passed 11/11.
- `git diff --check` passed.

The full `make check`, VM sanitizer/stress suites, Windows regression suites,
portability suites and host matrix remain required integration gates. These
focused results do not substitute for those gates or claim M5 complete.

## Review follow-ups

Native safepoint snapshots now go through owning instruction-set APIs; the
shared runtime does not inspect either engine's frame storage. Focused
collection/stack-growth acceptance was repeated after this correction.

`invokeDeferred` exposes `{result, callbackException}` before propagation.
The fixture returns a newly allocated native pointer after a callback raises,
then proves the annotated destructor reduces the native allocation count to
zero. Ordinary `invoke` releases an otherwise unreachable pointer registry
identity before raising; native ownership adapters must use the deferred API
because the generic bridge cannot infer a deallocator.

Pending exceptions and C failure latches belong to individual native-call
activations. A native fixture invokes two callbacks after the first raises;
the second uses its distinct message failure value without entering SML.
Nested deferred calls consume only their own pending exception. Stack,
register, JIT, runeopt, four Windows VM variants, the complete FFI sanitizer
gate and documentation checks passed again with these regressions.

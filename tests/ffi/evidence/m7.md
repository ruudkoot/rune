# M7 core SDL3 evidence — 2026-10-23

Milestone status: **planned**. The component implements all 53 agreed functions;
closing M7 still requires the roadmap's preceding milestone gates and final
integration acceptance. This receipt distinguishes executed checks from those
remaining open. It does not close M4, M5, M6 or M10.

## Delivered artifacts

- `ffi/sdl/core.ffi`: all 53 original declarations with reviewed ownership,
  nullability, output directions, text boundaries, errors and explicit raw
  names. The reusable policy validator accepts all 53 against original headers.
- `lib/sdl`: sealed, documented `SDLFn` projection, generated raw/layout input
  signatures, abstract equality handles, dependency guards, copied events,
  UTF-8 text, scoped pixels and ownership transactions through `ForeignOwner`.
- `ffi/sdl/native.build`: generated immutable build-set selection through an
  explicit `SDL_GENERATED` path variable; no arbitrary command execution.
- Generated original-header field adapters for `SDL_Surface.pixels` and
  `SDL_TextInputEvent.text`; SML owns event and surface semantics.
- `tests/ffi/sdl`: bounded regeneration/C compilation and shared semantic smoke
  source, with native, sanitizer, Linux GUI and both Windows entrypoints.
- `examples/sdl/hello.build`: an interactive software-rendered GUI example.
- `docs/ffi/sdl.md`, generated library documentation and dependency checks.

The sidecar's `sdl-core-v1` adapter capability explicitly delegates the public
projection to `SDLFn`; its raw scalar/pointer calls and complete target layout
are generated by `runeffi`. The manifest does not claim automatic synthesis of
the event sum type or scoped pixel callback. Every native call, including
resource destructors, uses the generated descriptors.

## Observed failures and repairs

- Initial text copying requested a one-megabyte view of a pointer whose known
  Rune allocation was shorter. It correctly failed the native bounds guard.
  Strings now read one byte at a time through their first NUL within the cap.
- Initial consumed pushed-text cleanup attempted to release its storage before
  the returned pointer identity, triggering the live-dependent guard. The
  pointer now closes before its retained backing allocation.
- Windows initially sent an unsigned SML argument for `SDL_PixelFormat`, whose
  Microsoft enum ABI is signed. Projection now uses generated `enumSigned`;
  both Windows widths passed after repair.
- Initial Windows adapter linking included SDL's injected `WinMain`, yielding
  unresolved `SDL_RunApp`/`SDL_main`. Explicit `SDL_MAIN_HANDLED=1` fixes this
  without changing original headers. The first Windows64 CMake configure also
  omitted the cross C++ compiler; supplying it fixed configuration.
- A restricted Linux GUI run returned `No available video device`; the same
  test passed outside the sandbox against the existing desktop.
- The first sanitizer process passed 26 semantic checks, then LeakSanitizer
  rejected the ptrace sandbox at exit. The exact test passed outside it; the
  sandboxed run is not counted as clean acceptance.
- A direct documentation-runner invocation initially lacked
  `bin/rune-doc-check` (six failures, five canaries passed). Building that tool,
  regenerating documentation and running required `make check-docs` passed all
  11 cases. This was a missing local test prerequisite, not a waived check.

## Explicit delivery limits

No audio/GPU APIs, foreign-thread callbacks or `SDL_RunApp` are selected.
The public event projection preserves unknown kinds numerically; payloads for
those kinds require raw access. Public pixel scopes cover uncompressed SDL
formats; FourCC/YUV/compressed extents require explicit raw handling. Debug text
uses SDL's built-in ASCII font, not Unicode shaping. OS-generated event streams
and rendering pixels can differ across platforms. These are documented
capabilities, not silently guessed mappings.

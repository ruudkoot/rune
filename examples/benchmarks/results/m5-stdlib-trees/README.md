# Sandmark map and set selector validation

All eleven selectors pass their 308 primary smoke/normal cases across Rune's
O0/O2 engines and six managed native SML hosts. All twenty semantic invocations
pass 364 assertions, for 7280 passing assertions and none failed or unreached.
Native O0/O2 group labels repeat host-default builds rather than select native
optimization levels.

Complete original AVL shapes, ordered contents and invariants are recorded for
78 operation sequences, including ascending, descending and seeded random
updates. Original selector observations agree with independent models on 44
edge-count cases and all 28 selected profiles. A swapped-value map with an
unchanged aggregate digest is rejected by the full-content checker.

The port preserves OCaml 4.14.1 balancing, separate map/set node payloads,
cached heights, one comparison per visited node and traversal order. Portable
change flags preserve unchanged-path decisions and introduce explicit temporary
option allocations. Constructor argument evaluation can change rotation-child
allocation order. Global map baselines and per-run set construction retain
their respective scopes. Source quirks remain: map_remove repeatedly targets
the original zero minimum, and set_add_rem deletes original entries.

Forty-four normal Rune count samples agree. All eleven guarded processes exit
zero without a guard interruption. Thirty-three serial single fresh-process
native smoke samples pass as adapter diagnostics, separately from heavy
validation. These are not ten-sample comparative performance claims.

Complete selected benchmark sources, original run-plan entries, OCaml library
sources, source identities and notices are retained. The Sandmark Unlicense and
OCaml LGPL 2.1/linking-exception grants remain separate. Normal iteration
reductions and six selected large profiles are documented per selector.
Full final SML large repetitions remain unrecorded.

Raw canonical results and private development evidence have separate scopes.
Repository acceptance is recorded separately in the suite validation ledger.

The final repository acceptance run exits zero with 1214 profiles, including
all compiler, runedoc and runeopt cross-build comparisons. The first run was
interrupted during optimization-level checks and has no final result; its log
is retained separately as development evidence. No partial run supplies this
acceptance claim.

## Algorithm and variants

Use boolean-array chromosomes, cached float fitness, binary tournament selection,
full Theta(n) copying mutation, and a fresh population each generation. Preserve
Onemax's sequential float sum, strict fitter comparison with second-individual
tie selection, two tournament samples and every mutation probability draw.
Mutation p=0.4/n still draws when it changes no bit; it always allocates a new
chromosome. Do not replace arrays by packed integers in the measured kernel.
The independent packed-bit oracle is a separate implementation.

The source checks time*population_size>runtime after constructing next_pop.
It therefore constructs floor(budget/lambda)+2 new generations, in addition to
the initial population. Preserve that strict post-generation test and its extra
work. Budget zero still evaluates three populations. These are deterministic
fitness-work parameters, not wall-clock stopping conditions.

OCaml records/arrays become SML records with boolean Arrays and real fitness.
For loops become portable tail loops; order, allocations, parent sharing and
whole-population replacement remain explicit. Selected fitness values are
integers represented exactly by binary64, so exact fitness comparison applies.
All selected counters fit 31 bits. No parallel/runtime feature is added.

## Reproducibility, profiles and checks

Replace Random.State.make_self_init by the documented seed 42 initialization.
This is an intentional adaptation required for reproducible inputs. Preserve
OCaml 4.14.1 generator/selection/float operations using the reviewed shared SML
RNG; retain its original source and LGPL/linking-exception notices. Every
invocation resets the RNG/population, including repeated in-process runs.

Smoke uses chromosome length 16, population 16, budget 128; normal 128/128/10,000.
Large preserves source defaults 1,000/1,000/100,000. Tournament size 2 and mutation
chi 0.4 remain unchanged. Fixed source/reference populations cover every profile.
Check all final chromosome bits, each stored fitness, independently recounted
Onemax fitness, dimensions and the best fitness. The original prints only the
best float; the suite reports length:population:budget:checked after complete
validation. Reference parsing and scans are measured work.

A bit-packed/integer-popcount implementation independently agrees on every tiny,
smoke and normal individual. It confirms 6/176/10,368 evaluations, including the
source budget overshoot. All original deterministic profiles, including large,
complete with full final-population fixtures. Large SML execution is claimed
only where explicitly recorded. Numeric or RNG host failures remain failures;
no source stream or expected population is adjusted to hide them.

Semantic checks cover tie behavior, mutation allocation/draw count, certain
mutation, tournament sampling, exact budget edges, complete populations and
perturbed/missing results. The seed 42 source patch, original code, input/RNG
identities and independent reference are retained.

## Recorded native32 limitation

Both profiles raise the already isolated bounded-random threshold Overflow on
managed 32-bit SML/NJ. Six selection-dependent semantic checks fail at both
levels; mutation and other nonselection cases pass. Other native hosts and
all Rune engines pass. Preserve the generator expression, fixed seed and
population fixtures; see [the existing arithmetic report](../validation/smlnj32-random.md).
Failed configurations cannot contribute measurements.

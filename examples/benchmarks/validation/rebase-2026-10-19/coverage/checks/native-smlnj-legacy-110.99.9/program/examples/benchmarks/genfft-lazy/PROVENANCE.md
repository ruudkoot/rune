# genfft-lazy provenance

Selected collection/value evaluation: lazy.

## Algorithm and workload

Generate source text for unrolled radix-two FFT dependency graphs of sizes
4,8,...,2^(maximum+1). Emit bit-reversed input bindings, every butterfly's
add/subtract/multiply equations, shared root definitions, ordered output groups,
and exact SYNTH/sector text. The measured workload is source generation.
The .program fixtures are data, including the shell-looking header.

## Variants and source behavior

The lazy variant memoizes character heads and list spines; the strict variant
constructs those finite lists eagerly. Both preserve input/output name order,
bit reversal, zero-bit insertion, groups of eight output variables, separators,
trailing spaces and final newlines. Shared numeric-name strings remain shared
values when reused. The finite integer bit-list/fold helpers and scalar name
parameters use eager SML operations in both variants; their complete values are
needed by the selected generator. Int.toString replaces the Haskell decimal
formatter on this nonnegative domain. Fast2haskell's miraseq is a no-op.

## Portable SML97 translation and adaptations

Retain the recursive bit-list construction and left fold for insertZero, plus
the source enumeration, map, take/drop, grouping, concatenation and foldr1-style
glue. The latter stays partial on an empty collection and leaves a singleton's
separator unused. The generator constructs source characters for every repetition;
a fixture is used only by the checker. No generated program replaces the kernel.

Indices and shifts are nonnegative and bounded by the selected exponent 8.
Fixed Word32 shifts and div/mod2 implement the source scalar bit operations within
a width-independent domain. Every intermediate integer fits signed 31 bits:
the largest complete output has 426210 ASCII characters and sum+length 31387091.
The driver compares each checksum separately, avoiding a narrow sum of 300 large
checksums. Repeated formatted output has at most 4800 bytes in selected profiles.
There is no reachable floating-point or arbitrary-precision arithmetic.

Load the reviewed complete source fixture once per driver invocation, then compare
every newly generated character for each repetition, including EOF. The source
ASCII-sum/length checksum is also computed and validated. Full byte comparison
rejects a deliberately transposed fixture with the same checksum and length.
This additional checking cost is included in identical-SML compiler comparisons.
The driver formats every iteration's source checksum/newline contribution and
reports repetitions:checksum:emitted-bytes through controlled suite output.

## Compiler/runtime diagnostic questions

Investigate recursive generation, integer/name formatting, sharing, eager/lazy
character lists, concatenation, closure specialization, stack/heap growth and
collector retention. These are source-derived hypotheses until established by
measurement. Byte checking, reference loading, kernel generation and final result
formatting remain visible parts of the SML workload. Profiling/counts remain
separate from headline timings.

## Profiles, correctness and references

| Profile | Maximum exponent | Repetitions | Generated bytes per iteration | Suite result |
|---|---:|---:|---:|---|
| smoke | 3 | 1 | 5532 | 1:417707/5532:12 |
| normal | 6 | 300 | 79360 | 300:5925859/79360:4200 |
| large | 8 | 300 | 426210 | 300:31387091/426210:4800 |

Normal/large retain original NORM_OPTS/SLOW_OPTS and all 300 iterations. Smoke
preserves FAST_OPTS and reduces only repetitions to one. Default limits apply.
Every program from exponent one through the maximum is generated in each
iteration. The input parameter is an exponent bound, not a universal size.

Unmodified GHC executions match every byte of all three 300-line fixtures.
Export-only observers record complete source for maxima 0..8. A separate renderer
using bit-mask insertion and reversed binary strings agrees with all selected
bytes. An independent evaluator checks all eight generated dependency graphs
against direct DFTs on nonuniform complex inputs, under documented complex
add/subtract/multiply and positive-unit-root meanings. This validates the graph
model rather than executing the historical target framework.

SML checks compare full source for maxima 0..8 in both modes, repeated output,
wrong/truncated/extra/checksum-colliding fixtures, character sharing, unused
separators and partial empty glue. Whole normal Rune O2 pilots retain all 300
iterations. Recorded host coverage and resource outcomes belong in validation.md.

[Cooley and Tukey](https://www.cs.jhu.edu/~misha/ReadingSeminar/Papers/Cooley65.pdf)
provide algorithmic background and [Partain](https://doi.org/10.1007/978-1-4471-3215-8_17)
provides suite context. Exact source/history observations and independent graph
checks have their recorded evidence; performance questions remain hypotheses.

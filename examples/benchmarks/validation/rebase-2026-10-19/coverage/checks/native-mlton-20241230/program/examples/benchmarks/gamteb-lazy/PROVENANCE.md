# gamteb-lazy provenance

Finite numeric evaluation: lazy.

## Algorithm and workload

Transport deterministic gamma-ray particles through the source carbon-cylinder
model. Select collisions and surfaces, apply photoelectric absorption, Compton
scattering and pair production, split particles or perform Russian roulette,
and accumulate escape/scatter/transit weights and twelve statistics.

## Portable translation and source behavior

Use SML97 for physics, generation, checking and output. Preserve binary64 Double
operations, named scalar sharing, source branch guards, list order and balanced
source splitting. Both policies keep control/result/statistic streams memoized.
The lazy policy defers finite scalar/point payloads; the strict policy constructs
finite numeric payloads after source branch selection. Both share each transport
call's result/statistic pair rather than recomputing particle paths.

Preserve the source's numerical definitions and historical quirks:
cylLen2 is 30, despite its square comment; surface-distance ties select the
second candidate; the plane guard is independent of direction sign.
The isotropic formula does not normalize the resulting direction vector.
Its rsq>1 rejection branch contains a self-dependent seed binding; an invalid
seed 5.1 produces the original GHC loop exception. The translation retains
cyclic memo demand for that branch. Valid generated source seeds do not demand
it in the recorded profiles. Rotation's pole guard avoids unused divisions.
Zero or negative source counts still generate one particle in the kernel;
the public driver accepts positive profile counts.

The original real-valued random generator keeps its truncate/divide/multiply
remainder stage. Selected integer conversions stay far inside signed 31-bit
range, as recorded by the independent model. Constant tables remain shared
indexed collections; private arrays build accumulations in source association
order. Preserve raw result order and the source's raw output labels, which
call the particle type index and the energy bin type.

Consume raw results first, then accumulated statistics, then the 105-cell result
array. Retain the shared streams across those consumers. Only the first element
of each constant table appears in the output prefix. That prefix is a memoized
lazy constant, forced on its first consumer, as the source CAF requires.

GEN17 formatting replaces GHC's Double spelling. Every observed number is finite
and must roundtrip exactly, including zero sign, before its formatted output is
accepted. The full buffered text keeps the source field/table ordering and is
consumed by a Word64 polynomial hash modulo 2^64, checked by an independent
reverse polynomial. Buffering formatted pieces is an output allocation
adaptation. A stable repetitions:result-count report replaces 200 printed
compiler-dependent decimal hash values.

## Profiles and correctness

| Profile | Source particle count | Repetitions | Raw results per run |
|---|---:|---:|---:|
| Smoke | FAST 100 | 1 | 118 |
| Normal | NORM 1000 | 200 | 1231 |
| Large | SLOW 5000 | 200 | 5913 |

All profiles use source seed 0.5, energy 6, unchanged cross sections and the
suite's default limits. Smoke reduces only repetitions. Normal and large retain
their original iteration counts.

Unmodified GHC runs match all three complete stdout fixtures. Export-only
observers expose ordered raw results/statistics, output text and accumulated
arrays. A separate eager LIFO event-queue model agrees exactly on every raw
value for 1, 2, 3, 10, 100, 1000 and 5000 particles. Independent ordered sums also
match all twelve GHC statistics and all 105 array cells exactly.

Primary checks require exact result counts, particle kinds, energy bins and the
first ten integer-valued statistics. Raw/accumulated weights and the four table
values use absolute 1e-11 plus relative 1e-10 bounds; zero accumulations remain
exact. These are source-result error bounds. Expected numerical references
retain every raw result and full aggregates. Auxiliary checks additionally
observe raw statistic order and 46 source arithmetic cases.

Tests perturb every result/statistic/array position, check interior tolerance
acceptance, reject nonfinite and malformed references, validate modular hashes
and exercise terminal-field demand and seed sharing. Direct arithmetic
diagnostics use separately documented tighter bounds, and retain host failures
instead of altering source arithmetic or benchmark defaults.

[The host-result note](../validation/gamteb-host-results.md) distinguishes
nursery-sensitive corruption, decimal roundtrip failures, generic real tuples
inside references and ordinary mathematical approximation differences.

## Literature and diagnostic questions

[Burns et al., Vectorization on Monte Carlo particle transport: an architectural
study using the LANL benchmark GAMTEB (1989)](https://doi.org/10.1145/76263.76265)
studies vector implementations and data motion for the historical workload.
The author-uploaded abstract and bibliographic record were reviewed; the full
paper fetch timed out. This port follows the sequential Haskell implementation.
[Partain's nofib paper](https://doi.org/10.1007/978-1-4471-3215-8_17)
provides functional-suite context.

Investigate floating-point boxing, shared scalar/point payloads, deferred terminal
coordinates, source-tree shape, paired result/statistic retention, concatenation,
array accumulation and output allocation. These are source-based diagnostic
questions. Reference agreement and measured counts are recorded separately;
the historical paper's vector speedups do not establish SML performance claims.

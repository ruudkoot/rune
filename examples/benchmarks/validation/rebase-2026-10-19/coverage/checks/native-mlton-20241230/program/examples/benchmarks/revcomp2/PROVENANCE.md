# revcomp2 provenance

## Algorithm and workload

Reverse each FASTA record's sequence, complement uppercase and lowercase ASCII
through a 256-byte lookup table, and emit at most 60 sequence bytes per line.
The source retains a reversed list of input lines, walks each line backwards,
and writes through a 61-byte mutable buffer whose first byte is a newline.
The port keeps that algorithm, buffer index convention and retained record.

## Known variants and exact source behavior

This variant stores strings in a list and uses a small byte buffer rather than
reversing a whole contiguous record in place. Preserve its handling of header-only
records (no added newline), consecutive headers (concatenated), a sequence without
a header (leading newline), blank lines (record flush), terminal lines without LF,
60/61-byte boundaries, ambiguous IUPAC codes and unknown bytes (space).
OCaml input_line removes only LF: CR remains in headers and maps to space in
sequence data. These source behaviors are recorded rather than normalized to a
different FASTA reader's conventions.

## Portable translation and adaptations

SML97 TextIO.inputLine replaces OCaml input_line, explicitly removing its terminal
LF. String lists, Word8Array lookup/buffer storage and descending indexed loops
preserve traversal and output order. An output callback replaces stdout; the
streaming BinIO reference checker consumes every emitted byte and verifies EOF.
Its I/O and validation are measured work. The source's catch-all read termination
is retained, and the input is closed at the end or after a callback exception.
All mutable buffers and indices are reconstructed on each invocation.

The source hardcodes input25000000.txt. The suite accepts an explicit controlled
input path and reference path. Reference runs keep the original fixed filename
in fresh working directories; no source algorithm edit is required. Output is
reported as a validated byte count only after full equality, not a hash-only test.

## Compiler/runtime questions

Record retention, list nodes, generic byte-array representation, input strings,
buffer accesses, tail calls and callback/checker overhead are source-based
performance questions until established by compiler inspection or measurement.
SML comparisons use identical sources. OCaml supplies correctness references.
The workload is sequential and needs no FFI, parallelism or runtime extensions.

## Inputs, validation and references

Fixed smoke/normal/large inputs are generated by the same pinned Sandmark fasta3
with parameters 1,000 / 50,000 / 500,000, seed 42, width 60 and sequence lengths
2n/3n/5n. The ALU sequence and distributions are embedded source literals;
there is no separately acquired dataset. Retain the generator's original author
credits, notice, source identity and every generated input/output identity.
Large is an explicitly reduced scaling profile. Dune's 25,000,000 default and
5,000,000 auxiliary input remain documented; neither full generator input is
claimed as an executed revcomp2 profile in this import.

Original OCaml outputs agree byte for byte with an independent implementation
that joins each generated record, reverses/complements it and wraps at 60.
Eleven original edge fixtures specify the unusual source formatting. Semantic
checks consume these fixtures and the complete smoke output; deliberately
corrupted, truncated and extra references must fail. Large SML execution is
claimed only when separately recorded. The retained source/header and suite
measurement survey provide history and methodology; FASTA itself does not define
this implementation's exceptional-input behavior.
